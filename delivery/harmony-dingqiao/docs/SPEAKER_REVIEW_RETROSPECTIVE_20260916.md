# 角色分离修复：合入复盘

## 本次交付边界

修复单人被短片段反复建档、历史混合上下文抢占身份、重叠通道在临时编号相同时丢失证据，以及标点/字节 token 导致最终文本不能按角色切分的问题。Harmony 与 Android 使用相同身份规则。Demo 区分角色中间结果和最终结果，并支持通过文件输入检查正常回调。

四人会议整体精度仍未通过；本次合入不能关闭多人精度问题或作为正式离线交付声明。相同人的临时编号经过纠正后收敛可以接受，编号切换次数只用于诊断。最终误认、未知时长、重叠覆盖和生命周期分别报告。

## Review 结论和有用的用例

| 风险 | 验证方式 |
|---|---|
| 限制单人误分时，把真实新人也挡住 | 首个短角色、已知短句、真实第二人和第四人分别断言 |
| 同一短片段在多个重叠窗重复出现，累计权重被当成长发言 | 重复 1.2 秒上下文不能累计满足 3 秒建档条件 |
| 没有当前发言证据的历史混合声纹建立假角色 | 原始差分 `[1,2,2] → [1,1,-1]`；当前查询不能更新身份档案 |
| 假角色抢占第四个名额，真实第四人变成未知 | 新增两端用例：旧代码 `[3,-1]`，修复后 `[-1,3]`，最终恰好四人 |
| 四舍五入把不足 3 秒的语音提升为合格新角色 | 两端分别验证 47,999 与 48,000 个 16 kHz 采样点；前者不能建档，后者允许 |
| 两个临时 UNKNOWN 或相同编号导致重叠证据被删 | 保存通道对应关系，部分重映射后仍恢复正确的次要说话人 |
| 句末标点和中文跨 token 字节使角色切分失效 | 保留完整字符、首字节时间戳和全部文本；ITN 改词不能猜测对齐 |
| 为补齐声学空隙而把不确定发言强行认人 | 只有已观测角色一致时补空隙；明确 UNKNOWN、多角色、重叠均不补 |
| 窗口定稿后又改身份 | 窗口发布后不回写、不重复发文、不复用句子 ID，跨窗文本保留 |

新增第四人用例在修复前稳定失败，假角色占用编号 3、真实第四人返回 -1；修复后通过。它直接验证容量保护，没有修改人数上限或放宽断言。其余已有且有效的回归用例保留。

Review 另发现 Harmony 的最终观察时长使用四舍五入，47,999 个采样点被记为 3,000 ms，最终阶段错误建立第二人；在线判断与 Android 均拒绝。新增用例先得到 `speakerCount=2` 的红灯，再将该时长向下取整，与 Android 一致。实际时间线仍按原规则输出，没有改变 3 秒条件或取样范围。

## 复盘

1. 单人修复不能只验单人。3 秒门槛曾改变剩余名额，使既有混合上下文缺陷变成新的多人误认；已用固定 PCM、声学输出和单变量差分定位并修复。
2. 查询当前发言和建立长期身份承担不同责任。短句可以查询已知角色；登记额外角色要有足够独立语音和当前输出证据。不能拿重复历史上下文凑时长。
3. 四人改六人的实验把 6.03 秒未知变成同样时长的误认，没有降低总错误。按“优先避免认错人”的要求保留四人默认值。
4. 先固定内部状态找第一次错误，再用真实公共回调验收。内部候选 last 日志不能替代调用方收到的 last/complete 顺序。
5. 64 MiB 是通用压测阈值，不能单凭它判断会议缓存是否泄漏。原始 FAIL 保留；会议资源预算需要独立的长时稳定性证据。

## 仍需跟踪

- **多人精度 OPEN**：四人 `L_R003S01C02` 片段最终误认 19.23 秒、未知 60.41 秒，DER 46.84%；局部分割通道混入不同人及同人声纹变化仍未解决。真实新人只留下短插话时可能保持未知。
- **快速喂入和会议资源 OPEN**：旧包同条件也出现结束异常；不得归为本次回归或改阈值后宣称通过。正常速度的两段真机验收不能替代长会议资源验收。
- **诊断计数 OPEN**：内部候选 last 可重复计数，直接公共回调没有重复 last；这是独立的观测问题。
