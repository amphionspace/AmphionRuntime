# HarmonyOS ASR SDK 0.3.25 升级说明

本版相对 0.3.24 有**两处产品变更**，一处修角色归属，一处改热词权重。
公共接口、回调顺序与角色结果格式不变，接入代码无需修改。

**本版会改变识别文本**：调用方热词的生效强度提高（见第二节），此前被同音词压过的业务专名
现在能正确命中。界面上若有基于识别文本的正则或关键词匹配，请按第二节复核。

运行时版本为 0.3.25，版本日期为 2026-10-22；商用授权的维护期限须覆盖该日期。

---

## 一、角色归属：仅有未识别次要人声重叠时不再丢弃主讲人（问题 #36）

### 1.1 现象

一句连续的话被拆成两段显示，前半段标为「角色1」，后半段标为「其他角色」，
而这句话覆盖范围内的每一个声学片段其实都指向同一个人。

### 1.2 成因

显示句的归属门禁此前过于保守：只要与该句相交的任一声学片段带有重叠标记、或带有任何次要
人物编号，就放弃整句的归属。实际上「次要人物是未识别的（UNKNOWN）」并不能证明主讲人换了人。

在客户反馈的录音上，这导致 0.69 秒的重叠作废了 6.12 秒的文本，0.66 秒的重叠作废了 3.48 秒的
文本。有界 UNKNOWN 回填也救不回来 —— 两段都超过了它 2500 ms 的上限。

### 1.3 本版改法

同一文件里已有 `blocksBackfill` 实现了正确的契约规则：**已识别的次要人物、或没有任何具名来源
的重叠，才阻断归属；仅为 UNKNOWN 的次要人物不阻断。** 显示门禁现在复用这条规则，与回填层对齐。

同时修正了另一处：此前只要某句成功归属，发布出去的次要人物编号就会被清空，把这句话实际
观测到的未识别人声吞掉了。现在会保留。

### 1.4 实测验证

在客户录音上，`speakerIndex = -1` 的句子由 2 句降为 1 句；被修复的那处空隙，其次要人物编号
由 `[1, -1]` 变为 `[-1]`。

### 1.5 对接入方的影响

- 原先被误标为「其他角色」的句子，现在会带上正确的角色编号。
- `secondarySpeakerIndexes` **非空不等于重叠**。该字段记录句内观测到的其他人物（可能是 `-1`
  表示未识别），判断重叠请使用 `overlap` 字段。此约束自 0.3.8 起已生效，本版未改变其语义。

## 二、热词：调用方热词权重提高到 3.0，预置池保持 1.0

### 2.1 现象

两字业务专名会被同音常用词压过。实测中一个两字机构简称在每一句里都被替换成了与它同音的常用词。

### 2.2 成因

此前调用方传入的热词（`sysGeneralLexicon`）与警务预置池（车牌 / 派出所 / 术语）共用同一个
全局权重。该权重曾为了抑制车牌过度偏置从 3.0 下调到 1.0，调用方热词也被一并压低。

### 2.3 本版改法

调用方热词改为**逐词显式加权 3.0**；预置池不带显式分数，继续沿用全局权重 1.0，
保持 Police 1.4.0 的校准和车牌 A/B 证据有效。

3.0 是评测得到的工作点：热词精确命中率 **76.41% → 96.12%**。

调用方热词若与预置词重复，按裸词去重，只入图一次。

### 2.4 接口语义收窄

`AsrConfig.hotwordsScore` 的含义由「全局热词权重」收窄为**「未逐词标注时的兜底分」**。
入参格式不变，不需要改调用代码。

### 2.5 诊断字段修正

诊断流里的 `hotwordCount` 此前读取的是 `StartParams` 上并不存在的 `hotwords` 字段，因此恒为 0，
排查热词未生效时会误导成「热词没传进来」。现在改为统计引擎级的 `sysGeneralLexicon`。
该字段仅用于诊断，不影响识别。

## 三、未改变的部分

- 识别模型、角色分离算法、阈值、窗口长度、hop 与提交周期：均未改动。
- 公共接口、回调顺序（final / last / complete 生命周期）、角色结果结构：均未改动。
- 0.3.24 引入的角色分离计算量上限（训练集 512、短 run 候选 32）：保持不变。

---

## 四、已知未解决项

公开角色编号在部分录音上会出现**不从「角色1」开始**或**中间号段跳号**，
以及说话人数较多时部分语音落入「其他角色」。

这两类现象的成因、实测证据与处置建议见随包文档
`DIARIZATION_ROLE_NUMBERING_29_77_EXPLAINED_20261022.md`。
其中编号不连续部分可在集成侧做一次号段压缩即消除，本版未改动 SDK 侧编号发放逻辑。
