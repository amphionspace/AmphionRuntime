# 双端 ASR 交付邮件模板

适用于 Android/Harmony，可按本次范围删去未交付平台。先填写[调用方变化核对表](../../../CALLER_CHANGE_CHECKLIST.md)，再替换下方占位项；不要直接复制历史版本的能力、指标或通过结论。实际邮件放最终 ZIP 外，不自动发送。

写作要求：

- 用客观、普通项目成员能理解的语言，写“相较上一实际交付改了什么”和“对方需要做什么”，不用宣传标题或不必要的模型/实现名称。
- 需要业务方调整的行为放在前面，包括默认设置、等待时间、结果更新方式、评分含义及两端差异。没有变化的内容不列为新增。
- 数字注明平台、样本和比较基线；专项测试不冒充最终包验收，新方案内部优化不冒充与上一交付的对比。
- 邮件详略按用户要求调整，但不能虚构已通过、全部兼容或问题已解决；真实状态和影响交付结论的问题保留在配套报告中，需要采取行动的限制必须让接收方可见。
- API 字段、调用代码和完整生命周期契约放接入文档，邮件只保留接收方采取行动需要的信息。
