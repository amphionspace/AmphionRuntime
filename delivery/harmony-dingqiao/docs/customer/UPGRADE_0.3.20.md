# HarmonyOS ASR SDK 0.3.20 升级说明

本版基于 0.3.19，主要改进角色分离在长会议下的运行成本与发热，并修正若干角色归属问题。公共接口、默认参数、回调顺序和角色结果格式沿用 0.3.19，调用方无需修改接入代码。

## 替换方式

1. 使用本包的 `amphion_dingqiao.har` 替换项目中的 0.3.19 HAR。
2. 同步项目依赖后重新构建，确认项目实际加载的是 0.3.20。
3. 如使用 Diagnostics SDK，整组替换对应 HAR，避免混用两版组件。Demo 源码及已签名 Demo 随完整包提供。

运行时版本为 0.3.20，版本日期为 2026-10-07；商用授权的维护期限须覆盖该日期。

## 调用方需要注意的三处行为变化

**角色推理超时由 10 秒改为 60 秒。** 原生调用无法中途停止，超时只会丢掉此后所有窗口并清掉已处理音频的临时角色。后台降频时单个窗口可能需要约 24 秒但仍在推进，因此放宽到 60 秒。收尾等不及时，由已有的收尾超时抢救保住已推理部分。如果您的上层对单次角色回调设有更短的等待上限，请相应放宽。

**长会议中临时角色的刷新变慢。** 预览聚类改为按开销限流：下一次预览至少要等音频推进"上次预览耗时 × 10"，并且不少于 10 秒。短会议仍每 10 秒预览一次。定稿与最终角色结果不变，只是会议越长、临时角色的更新间隔越大。依赖临时角色即时性的界面需要知悉这一点。

**角色分离的常驻内存上升。** Harmony 角色窗口改为最多两路单线程并行计算，带来第二个 encoder 实例和两路中间张量。配合本版改用的 per-channel INT8 encoder（打包体积由 20.3 MiB 降到 5.2 MiB），16 分钟会议的进程 RSS 峰值实测为 738.7 MiB。请确认宿主的内存预算。

## 其他修正

角色归属与身份：

- 后处理改写 final 文本时保留角色区间，警务增强后的 final 不再丢失 speaker spans。
- 容量上限触发时只匿名化溢出的身份，不再波及已建档说话人。
- 容量即将丢弃说话人前，先折叠被拆成两个号的同一人。
- 发射滞后的 ASR token 归属到其实际语音位置，并在抢救证据末尾停止该归属。
- 重叠语音之后的 token 保留以待回填。
- 没有运行证据的语音改用其通道向量命名。
- 收尾超时时保留已推理出的说话人。

运行与资源：

- 后台降频下较慢的角色推理不再被误判为停止。
- 进程被杀后遗留的 job 文件会被清理。
- RSS 告警限定到显式资源预算，不再对角色分离给出无预算的告警。

授权：

- 支持多包离线授权。
- 旧交付的授权校验继续有效。

Android 侧同期修正（与 Harmony HAR 无关，供双端对齐参考）：CT 文本间距与说话人 token 对齐；按运行证据在无损会话历史上聚类；`vadEnd` 尾静音与语音边界事件修正；警务重复指示代词需要车牌上下文。

## 验证范围

**真机**：华为 Mate 80，OpenHarmony-6.1.1.120，API 24，arm64-v8a，USB 供电、亮屏。AISHELL-4 公开会议 960 秒、20 ms 实时喂入，`diarization-windows` 模式。结果：停止后收尾 3942 ms（门禁 15000 ms）、空 final 率 0、角色分离生命周期 1/1 通过、无异常回调；角色分离 RTF 0.3190，平均 CPU 238.0% 单核等效，机身温升 6.35 °C，RSS 峰值 738.7 MiB。

**编译兼容**：按 0.3.19 起的做法，用独立 OpenHarmony 6.1 / API 23 公开 SDK 6.1.0.31 的 `es2abc` 检查 HAR 内全部 TypeScript 实现。

**本版语种范围为中英（ZH_EN）。** 不包含粤英模型，粤英能力不在本批交付范围内；HAR 已声明的粤英接口能力未删除，但缺少模型无法启用。语种范围的恢复须作为独立交付范围评审。

**未覆盖**：16 分钟内机身温度单调上升且结束时仍在上升，更长会议的热表现未验证；息屏场景未在本机型复测；分阶段对齐的内存证据未采集，通用 RSS 增长判定保持 INCONCLUSIVE；客户 Windows 工程的完整编译未覆盖。

本版不包含 TTS 模型；目标说话人增强仅保留接口，不包含所需模型，不能启用。
