# Amphion HarmonyOS 离线 ASR 授权方案

## 1. 方案

SDK 使用本地签名 License，不依赖公网激活：

1. 我方私钥对授权声明签名。
2. SDK 内置生产验签公钥，在设备本地验证签名。
3. 绑定范围以本批授权声明为准，证书或设备白名单非空时须满足对应条件。
4. `sdkMajor=0` 表示不限制主版本，`maintenanceUntil` 为空表示不限制维护期；不能假定每批都使用这组值。
5. `expiresAt` 控制运行有效期；为空时表示已授权版本不按日期停机。

`amphion-license.lic` 由签发方受控提供，或继续使用适配当前 SDK 的有效授权；签发私钥不进入交付物。

## 2. 授权声明

License 为 UTF-8 JSON 信封，签名覆盖原始授权声明字节：

```json
{
  "payload_b64": "<base64 claims>",
  "alg": "SHA256withECDSA",
  "sig_b64": "<signature>"
}
```

授权声明记录客户标识、授权编号、能力、期限与适用范围。请核对包含 `ASR`，并按实际声明确认设备、证书、主版本及维护期条件。

## 3. 应用与设备范围

未绑定设备的体验授权无需宿主提供硬件 SN 或 ODID；含设备白名单时，必须提供与签发依据一致的标识。含证书约束时还需匹配宿主签名。不能将某一批未绑定授权的使用范围推广到其他授权。

## 4. 版本规则

- `sdkMajor=0` 时不限制 SDK 主版本；设置正数时需匹配。
- `maintenanceUntil` 非空且 SDK 发布日期晚于该日期时，升级权益失效，需要续期。
- 维护期到期不会自动改变已经安装版本的 `expiresAt` 语义。
- `expiresAt` 非空且运行有效期到期后需重新签发，实际期限以授权文件为准。

## 5. 集成与错误处理

公共调用顺序和代码示例见交付包内 `docs/INTEGRATION.md`，授权错误码见 [LICENSE.md](LICENSE.md)。

授权失败时应记录错误码和脱敏 message，不得把 License 原文、设备标识或私钥材料写入日志。纯离线环境无法实时吊销已经离线安装的旧授权；吊销清单需随下一次升级或运维介质进入现场。

## 6. 边界

离线验签可以阻止普通复制、篡改和设备误用，但端侧代码理论上仍可能被逆向或替换。需要更强保护时可增加 native 完整性校验和系统级可信执行环境，代价是适配、排障和升级复杂度上升。
