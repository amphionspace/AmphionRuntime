# HarmonyOS ASR SDK 0.3.21 升级说明

本版基于 0.3.20，唯一的功能改动是让角色分离的说话人 encoder 可以跑在麒麟 NPU 上，从而降低长会议的 CPU 占用与机身温升。公共接口、默认参数、回调顺序和角色结果格式沿用 0.3.20，调用方不修改任何接入代码即可升级，行为与 0.3.20 完全一致。

## 替换方式

1. 使用本包的 `amphion_dingqiao.har` 替换项目中的 0.3.20 HAR。
2. 同步项目依赖后重新构建，确认项目实际加载的是 0.3.21。
3. 如使用 Diagnostics SDK，整组替换对应 HAR，避免混用两版组件。Demo 源码及已签名 Demo 随完整包提供。

运行时版本为 0.3.21，版本日期为 2026-10-08；商用授权的维护期限须覆盖该日期。

## 默认行为不变

说话人 encoder 的默认后端仍是 CPU。**不做任何配置改动时，0.3.21 的运行行为与 0.3.20 相同**，升级本身不会改变发热、内存或识别结果。NPU 是需要显式开启的可选项。

## 如何开启 NPU（可选）

在 `StartParams` 的调度配置里设置 `scheduling.diarizationEncoder`：

| 取值 | 行为 |
|---|---|
| `'cpu'`（默认，或不设置） | 沿用 0.3.20 的 ORT INT8 encoder |
| `'npu'` | 要求设备存在麒麟系 NNRt 加速器且 MindIR 资产可用；任一条件不满足则加载失败并报错，不会静默退回 CPU |
| `'auto'` | 优先使用加速器；**仅在构造阶段**失败时退回 CPU，推理开始后不会中途切换 |

`'npu'` 与 `'auto'` 需要包内的 `community-wespeaker-encoder.fp16.ms` 资产，本包已随 SDK 提供。设备侧要求：OpenHarmony 的 NNRt 服务可用，且存在名称包含 `kirin` 的加速器。

每个角色窗口的结果都会带回实际使用的后端，便于您在自己的日志里核对，而不必相信配置本身：

- `encoderBackend`：`"cpu"` 或 `"npu"`
- `encoderDevice`：实际选中的 NNRt 设备名，CPU 路径为 `"cpu"`
- `encoderMs`：该窗口 encoder 单次推理耗时（毫秒），不含池化与特征

## 开启 NPU 后的实测收益

Mate 80（`VYG-AL30`，OpenHarmony-6.1.1.120）上同一个 HAP、同一段 AISHELL-4 会议音频、每轮都从同一冷却起点开始：

| 连续时长 | CPU 后端温升 | NPU 后端温升 | 机身峰值 | 进程 CPU（单核等效均值） |
|---|---:|---:|---|---:|
| 16 分钟 | +6.86 °C | +4.79 °C | 41.14 → 39.17 °C | 235.4% → 204.4% |
| 30 分钟 | +8.90 °C | +6.11 °C | 43.20 → 41.07 °C | 240.4% → 208.3% |
| 60 分钟 | +9.26 °C | +7.13 °C | 44.90 → 42.59 °C | 249.4% → 212.8% |

- encoder 单窗耗时中位由 307.7 ms 降到 27.7 ms；1 小时连续运行时 CPU 后端因热降频升到 326.4 ms（p95 495.4 ms），NPU 后端全程保持 27.6 ms。
- 识别文本在两个后端上逐字节相同；角色标签的 10 ms 帧级一致率为 99.21%（16 分钟）与 100%（30、60 分钟）。
- 全程 USB 供电，充电本身使机身温度下限保持在 34–35.7 °C，断电场景的绝对温度会低于上表，但两个后端的差值可参考。

## 仍需知悉的限制

- **发热是缓解而非消除。** 开启 NPU 后 1 小时连续转写机身仍到 42.59 °C。剩余发热主体是 ASR 解码，不在本版改动范围内。
- **角色身份精度未因本版重新验收。** 上表只说明两个后端结果等价，不构成角色精度结论；MindIR 资产的状态仍为"已转换、未做设备精度验收"。0.3.20 遗留的角色精度验收阻断在本版继续有效。
- **1 小时连续运行的内存增长超过内部通用阈值。** 两个后端都超过：CPU 后端 +108.3 MiB、NPU 后端 +178.6 MiB（进程 RSS 峰值分别为 1071 MiB 与 1185 MiB）。识别与角色功能本身未失败（无异常回调、空 final 率 0）。若您的宿主有长会议常驻内存预算，请按 1.2 GiB 量级评估，并避免单会话连续运行超过 1 小时。
- **`auto` 的真机验证未完成。** 本版仅对 `cpu` 与 `npu` 两个取值做了真机实测，`auto` 的退回路径只有构造期逻辑保证。生产环境建议显式指定 `cpu` 或 `npu`。
- 本批语种范围仍为中英（ZH_EN），不含粤英模型；不包含 TTS 模型；目标说话人增强仍只保留接口、不包含所需模型，不能启用。

## 建议的升级路径

1. 先按默认配置（CPU）替换 HAR 并回归，确认与 0.3.20 行为一致。
2. 在目标机型上单独开启 `scheduling.diarizationEncoder = 'npu'`，用 `encoderBackend` / `encoderDevice` 确认真的落到了加速器上。
3. 非麒麟机型或 NNRt 不可用的机型保持默认 CPU；不建议在未实测的机型上直接使用 `'auto'`。
