# 三人录音的断句等待与角色拆段（2026-09-16）

## 结论

本次修改缩短角色分离场景的停顿断句等待，并恢复带标点文本的按角色拆段。它不代表重叠说话的身份识别问题已经全部解决，也没有实现“模型一检测到换人，就立即强制结束 ASR 句子”。

用户确认现场共三人。原手机日志覆盖 160.22 秒，但 Demo 仅保存前 55 秒 PCM，明确标记 `truncated=true`。因此这段音频可以验证前段断句，不能代替完整现场复现或带身份时间标注的精度验收。

## 已证明的问题与修改

| 问题 | 证据 | 修改 |
| --- | --- | --- |
| 停顿后等待偏长 | 原现场 20 次 VAD endpoint 均等待约 1626 ms；endpoint 后处理为 18–95 ms | 仅 Demo 开启角色分离时使用 `vadEnd=800`；未开启角色分离的各业务配置和 SDK 默认值保持原值 |
| 字节编码和标点共同阻止按角色拆段 | 同一组 token、时间和角色边界，裸文本能拆成 S1 / UNKNOWN；插入逗号、句号后旧实现整段变为 UNKNOWN | Harmony、Android 先按 native BBPE 字节表精确恢复原文和时间，再对齐仅插入标点/空白的显示文本；跨 token 的 UTF-8 字符沿用首字节的时间 |

拆段在角色窗口提交或会话结束时生效。插入标点不再阻止拆段；真正的文字改写（例如 ITN 将“二十三”改为“23”）仍保留整段，不猜测数字内部的角色边界。UNKNOWN 和重叠角色策略不变。

## 真机验证

第一批 `ecfe2f1b` 的四段回放验证了 800 ms 参数，但实际拆段数仍为零。这成为继续定位 BBPE 的证据；不能将仅标点修复当作角色拆段完成。随后 `ea31459b` 的三段真机回放证明 BBPE 拆段生效，但发现单人句尾有 20 个字符落入无声学覆盖区，被新拆段标成 UNKNOWN。该候选版本记为失败并保留现场。

`9ced6004` 修复此回归：原始单人状态回放恢复全部 20 个字符；三人状态结果不变；四人状态只改变一处一致身份空隙（6 字），明确 UNKNOWN 保留。这里使用的是冻结回调分段边界，不是重新推理或整套真机验收。最终包只补跑有针对性的 47.26 秒单人公共 SDK 验收，并检查窗内未知、重叠、多个不同身份等相邻状态。

## 范围与未解决项

- 不把临时编号跳变后回正单独判作失败。最终错误归属时长和 UNKNOWN 时长分开报告。
- 短暂停顿也可能属于同一个人，缩短 VAD 会增加 ASR 段数；角色应由身份证据保持，不由句子编号决定。
- 无停顿的连续接话、真实重叠及 ITN 改写后的时间映射仍需分别处理。不能仅靠更低 `vadEnd` 解决。
- 前一批次四人控制样本的结束超时及长期资源增长仍在既有问题记录中保持开放；本次未修改相关状态机或放宽 64 MiB 检查。
- 这是候选分支上的针对性修复，未合入主线，也未完成正式发布门禁。
