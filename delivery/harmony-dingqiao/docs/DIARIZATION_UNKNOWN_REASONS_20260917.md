## 诊断记录与公共接口

只在现有 Harmony 诊断模式中增加 `DIARIZATION_UNKNOWN`，每个最终提交窗口一条，`stage=WINDOW_FINAL`，包含该窗口 UNKNOWN 主声学 turn 的时间和 evidence key：

- `RELATIVE_LEVEL_FILTERED`：本窗口定稿前被相对音量准入排除，不代表背景、不保证放开后能正确认回。
- `NO_VALID_CONTEXT_EMBEDDING` / `NO_VALID_QUERY_EMBEDDING`：相应上下文或查询向量不可用；日志不猜测是太短、重叠还是 extractor 技术失败。
- `IDENTITY_UNCERTAIN`：上下文满足音量条件，但现有建档/匹配路径仍未确认身份；不把它细化成未经证明的单一声纹模型原因。

同时记录 `speechRms`、`referenceRms`、`relativeLevel`、`relativeThreshold`、`absoluteThreshold`，以及上下文、通道 query 和连续段 query 是否可用。不存在的音量用 -1 表示，不把缺少证据写成音量为零。原因可并存；无 turn 的声学空隙和临时 update 不在这条最终窗口诊断的覆盖内。事件不包含音频、文字或 embedding。

不增加 SDK 公共字段：这些信息服务研发定位，不能向调用方承诺真实人物或背景分类；界面仍显示“未区分说话人”。诊断关闭时不收集这些记录，诊断异常不得影响定稿。单测覆盖开/关/抛错公开输出及档案相同；七组保存状态在新诊断开启后，公开结果与 `c19db6d5` 逐字段相同。

私有证据在原双人修复目录下 `owned-enrollment-gfoqu5qy/level-recognition-s1nxpj_i/`：`plan.json`、`candidate-assessment.json`、`decision.json`、`interval-audit.json` 和逐样本 baseline/candidate/diagnostic 状态。新代码仅诊断变化，Android 身份算法不变；新 HAP 的真机诊断及既定合入门禁须单独绑定新构建，不将旧包结果冒充新包结果。本 PR 不扩展到发布包或发布账本。
