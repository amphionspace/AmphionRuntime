# 安卓角色分离同步与 vadEnd 对照（2026-09-16）

## 结论

会议 Demo 保留 `vadEnd=800ms`。两端公共 SDK 的下限均为 500ms，传入 400ms 实际按 500ms 执行。本次不改 SDK 参数范围、角色容量或声学模型。

安卓 Demo 同步了角色的“中间结果 / 最终结果”、会议 800ms 停顿和固定 WAV 文件输入。两端页面均保留 SDK 角色编号（界面从 1 开始），不按当前可见人数重新编号。文字 `isFinal/isLast` 不代表角色已定稿；角色窗口回调才使标签最终化。

## 真机发现的两个独立同步缺口

1. **时间轴倒退**：安卓 native stream 重建后，token 时间从接近 0 重新开始，角色模型却使用整个 session 的 PCM 时间轴。基线第二句开始 680ms，早于第一句结束 1079ms。修复在真正重建/重置流时记录真实 PCM 原点，并在结果进入异步后处理前换算时间；native checkpoint 保留原点，内部预热及尾静音不计入真实 PCM。
2. **尾句被空结果覆盖**：真实 ASR 尾句已被角色结束流程接收，但还在等待角色窗口时，`onSessionStopped` 的延迟兜底再次送入空尾句，覆盖存储的末句。基线公开转写 327 字，角色窗口 343 字；差额是实际末句，不能称为窗口重复。修复让兜底检查终止结果是否已被接收。没有真实尾句时仍保留原兜底。

两项均来自修改 Demo 展示之前就存在的 SDK 路径。新增测试分别检查时间快照、文字/置信度保持、真实尾句与空尾句、唯一 last 后唯一 complete。后者已保存稳定红灯：期望“最后一句”，实际为空；修复后两条路径均通过。

**调用方迁移**：Android `AsrResult.timestamps` 及鼎桥结果的 `beginTime/endTime` 现在使用 session 输入音频时间轴，跨句不归零。若业务侧曾自行叠加前句时长补偿，升级后应移除该补偿，避免重复偏移。单位不变：前者秒，后者毫秒。

Review 另发现安卓页面按可见角色重新编号，与鸿蒙保留 SDK 编号的行为不一致。真机回归先证明 `speakerIndex=3` 被显示为“说话人 1”，再修正为“说话人 4”；相邻用例保护中间/最终标签、未知角色和最终结果拒绝迟到更新。该修改只影响展示，复用原 SDK 精度和阈值对照证据。

## 实验方法

- 两台 USB 真机：TECNO KI8（Android）、PSN-AL00（Harmony）。全部为文件输入，不使用扬声器或麦克风回录。
- 同一 AISHELL-4 `L_R003S01C02` 690–870 秒片段，16kHz 单声道 PCM16，180 秒内有 4 位标注说话人。
- WAV SHA-256：`ca8dabf80f0471bb5967557f8f05669e30ca893880f34eb4df83bc77165cfbd2`。
- 音频、RTTM 和原始文字来自 OBS `cuhk-anfeiweng-benchmark/asr-zh-en-eval-20260804/aishell4-test.tar`。声学身份指标与文字指标分别计算。
- 每个平台固定输入、20ms 喂入时钟、关闭警务增强；只改变 `vadEnd`。安卓修复前的失败现场单独保留，不作为修复后验收证据。
- 文字误差参考值使用原始标注按开始时间串接后的字编辑距离。含重叠发言排序和片段边界截断误差，仅用于本次相对比较，不代表正式 ASR 字错率。

## 安卓根因修复对照

最终 800ms 回放通过：token 时间单调前进，公开转写和角色窗口均为 343 字；修复前后的 28 条非末尾 final 文字逐条完全相同，唯一文字变化是恢复真实末句。无 error，显式 finish 前 last 为 0，结束后恰好一次 last 和一次 complete。声学身份指标保持不变。

## 鸿蒙结果

| 入参 / 生效值 | VAD 实测停顿 | 转写 final 数 | 文字误差参考 | 声学身份误认 | 声学未知 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 800 / 800ms | 826ms | 30 | 48.34% | 19.23s | 60.41s |
| 600 / 600ms | 602ms | 35 | 50.17% | 19.23s | 60.41s |
| 400 / 500ms | 506ms | 34 | 51.16% | 19.23s | 60.41s |

VAD 停顿来自 native 的已处理 sample 与 speech-end sample 差值，不能等同于界面显示延迟。声学分离指标未变：下调停顿主要改变文字断句和文字对应的角色，并没有解决重叠发言的声学身份错误。三个设置的 SDK 生命周期、角色窗口和资源门禁均通过。

## 安卓阈值对照

三个设置均通过时间轴单调、窗口文字守恒、无错误及唯一 last/complete 断言。

| 入参 / 生效值 | final 数 | 转写字数 | 文字误差参考 | 文字被标为未知角色的覆盖时长 |
| --- | ---: | ---: | ---: | ---: |
| 800 / 800ms | 29 | 343 | 62.91% | 33.36s |
| 600 / 600ms | 29 | 379 | 57.95% | 47.48s |
| 400 / 500ms | 31 | 355 | 58.28% | 34.16s |

安卓下调停顿可改善该片段的转写，但 600ms 增加了文字被标为未知角色的覆盖范围。三个设置的声学身份误认均为 19.22s、未知均为 60.41s。文字归属与原始声学 turn 指标口径不同，不应混用。结果不能直接迁移到鸿蒙，也不足以支持全场景降低默认值。

## 安卓文件输入入口

将 16kHz、单声道、PCM16、时长对齐 20ms 的 WAV 放到应用工作目录，显式启用文件测试，再点击开始。此入口走正常识别和角色窗口回调，不使用旧的转写对比回放入口。

```bash
adb push meeting.wav /sdcard/Android/data/com.amphion.dingqiao.demo/files/dingqiao_work/demo-test-input.wav
adb shell am force-stop com.amphion.dingqiao.demo
adb shell am start -n com.amphion.dingqiao.demo/.MainActivity --ez demoFileInput true
```

普通启动不带该参数时使用原麦克风入口。
