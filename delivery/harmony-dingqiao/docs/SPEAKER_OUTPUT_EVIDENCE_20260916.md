# 额外角色建档必须有当前发言证据

## 结论与范围

本轮修正了一个已证明的多人退化：较长的混合历史上下文建立假角色，随后把正确的当前发言改成这个角色。Harmony 与 Android 同步修改。四人会议的主要身份漂移仍为 OPEN，不能据此宣称整体精度通过。

- 改变：最终聚类登记第二个及后续角色时，除已有的单次观察至少 3 秒条件，还要求该聚类至少包含一次当前输出区间的 query embedding。提取器原有规则要求至少 1 秒真实单人语音；本轮不改变该门槛，也不借历史 PCM 伪造查询。
- 保持：首个角色、已知角色的短句匹配、在线临时结果、相似度阈值、四人上限、模型、ASR/VAD 参数、公开窗口冻结及 last/complete 顺序。
- 不处理：重叠语音解混、局部三通道容量、长会议资源问题及完整发布验收。

当前发言证据可以来自同一聚类的另一次观察。它只决定是否允许建档，查询向量仍不更新角色档案。证据不足时返回未知；真实新人只留下短插话时，也可能晚些获得编号或保持未知。

## 根因和退化归因

`M_R003S01C01` 的固定声学输入中，`w00000067:2` 有 3.510 秒建档上下文，但当前输出只有 0.673 秒，没有 query embedding。原代码仍将它登记为 S3。之后 `w00000068:1` 的当前查询对假 S3 的相似度 .636，对正确 S2 为 .570，导致 166–168.5 秒从正确 S2 改成 S3。

此前 `95b8f14c` 增加 3 秒门槛，释放了原来被更短虚假档案占据的名额，使这份混合上下文得以建档。同输入仅切换该门槛，误认从 2.80 增至 4.19 秒，证明它是此前修复暴露的错误建档路径及其实际退化，不能声称短句门槛完全没有多人代价。原现场与前后状态均保留。

新增两端用例在旧代码稳定得到角色 `[1, 2, 2]`，预期为 `[1, 1, -1]`；修复后通过。相邻用例保留首个短角色、已知短句、满足条件的真实第二人、先有独立发言再重叠、窗口冻结和查询纠错。既有模拟输入补齐当前输出查询；重叠用例增加真实单人区间，未放宽原来的双身份断言。

## 四人上限和否决实验

用户允许在改善精度时适度放宽上限。同输入直接改为六人，四人片段的未知减少 6.03 秒，但误认恰好增加 6.03 秒，输出六个身份，DER 不变。因此保留四人默认值。

以下仅为本机诊断原型，未进入源码或手机：整簇跨窗关联、按共有音频补身份、扩大模糊声纹集合、仅保留概率过半的建档帧，以及过滤采样后放宽至五人。它们分别增加其他语料误认、漏掉真实第三人或增加未知而未改善整体错误率，均否决。最保守的跨窗补身份在新增四人片段减少未知 2.23 秒，但原 COS 会议误认增加 .84 秒，仍未采用。
