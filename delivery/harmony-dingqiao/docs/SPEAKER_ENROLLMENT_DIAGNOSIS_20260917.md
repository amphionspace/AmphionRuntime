# 同人重复建档：状态分叉结果

2026-09-17。运行基线 `e7a1acefce8091ce004dba4d968b96b24a156306`，会话源码取自文档提交 `afe6d9e5`。本轮是根因实验，尚无通过验收的身份修复补丁；已有文字展示和有限 UNKNOWN 补全修复不受影响。

## 已确认的错误链路

固定四人录音的首个公开窗口止于 124.8 秒，实际第四人约 134.043 秒才出现。生产状态机却在第一个窗口建立了四份档案：S1、S4 的主要取样都来自同一个人。后来的真实第四人无法取得名额，大量输出 UNKNOWN。

同输入状态回放与已保存的手机输出一致：73 个声学窗口、143 个最终声学区间、两个公开提交边界。回放使用生产会话、聚类和注册表代码，省略 ASR 文本输入，不是一次新的真机验收。五份上下文 embedding 按原样本索引重新提取后，与保存值的余弦相似度均约为 1，样本数完全相符。

首个重复簇包含 `w00000050:1`、`w00000051:1`，对既有 S1 的相似度约 .55863，低于新增身份判定所复用的 .59。它满足时长和 query 存在条件，因而得到 S4。这里的“不足以接受为旧人”被转成了“足以建立新人”，随后成为不可回收的公开身份。

但这不是只挡一个候选就能解决的问题：较早的 `w00000031:2` 等片段也可建立重复档案。原标注与 MOSS 支持同人解释；尚未进行人工听审，不把交叉支持写成无争议真值。计分器的编号排列不用于解释建档人物。

## 同状态分叉

所有实验均为私有、非交付实现，没有修改手机或 SDK。阈值实验只执行预先记录的一个变体，不扫描到本片段通过为止。

| 实验 | 唯一干预及观察 | 结论 |
|---|---|---|
| 禁止第一个已证实重复簇建档 | 后续另一个同人簇取得 S4；真实第四人仍未知 | 单点跳过无效 |
| 首窗只容纳已知三个真实人物，作为诊断 oracle | 第四人到来后取得 S4；其独占、容差外语音的具名覆盖由 0 增至 15.96 秒，未知由 16.48 降至 .52 秒 | 证明容量占位是后来未知的原因之一；用了参考人数，禁止产品化 |
| 只清理首个重复簇的上下文取样 | 原标注与 MOSS 都支持的单人样本保留后，两份样本由 5.463/6 秒降为 1.886/2.566 秒，未达额外建档门槛；另一重复簇仍取得 S4 | 清理这两份输入不足以修复；取样同时改变向量和有效时长，不能单独归因于向量变化 |
| 按原 PCM 区间分摊重复观察权重 | 保留原向量与单次建档时长资格，只改变聚类贡献；同人仍重复建档，仅身份建立顺序改变 | 不实施权重去重改造来解决本问题 |
| 单独收紧新身份准入，不改旧人匹配 | 将新身份边界从 .59 改为 .59 减既有 .05 margin；前两个重复候选被挡，`w00000010:2` 等第三个候选又取得 S4（对 S1 约 .46723） | 拒绝此候选，停止该调阈值路线；旧 AISHELL3 查询校准不能证明新人判定有效 |

四人基线误认 19.23 秒、未知 60.41 秒。只清理首个重复簇后误认虽降至 2.73 秒，未知却增至 76.04 秒，实际第四人的独占语音仍全部未知，不能记为修复。PCM 权重实验的误认/未知与基线相同。

容量 oracle 的误认为 2.34 秒、未知 60.44 秒，但主人物的独占未知从 22.61 增至 32.75 秒，仍有 1.35 秒误归后来 S4。它证明因果，不是解决方案。误认/未知为原评估器的全片段口径；每人的独占覆盖另使用 250 ms 边界容差，不混用分母。

## 独立声纹样本检查

从同一原 PCM 中选择原标注与 MOSS 均支持、无其他标注说话人、连续至少 2 秒的区间，最长截至 6 秒。共 21 段，比较的样本不重叠，查询片段不参与对方建档。多数片段属于主人物，另外两人各只有一段；这些相关样本不是独立人群评测，不能据此宣布模型总体精度。

| 样本至少 3 秒 | 当前 ERes2Net | 服务器已有 WeSpeaker ResNet34 |
|---|---:|---:|
| 同人最小余弦 | .31975 | .25699 |
| 异人最大余弦 | .37406 | .32278 |
| 同人/异人比较数量 | 91 / 45 | 91 / 45 |

在这批交叉支持样本中，两套表示都存在同人、异人分数交叉。因此，不能仅凭对历史混合中心的一次查询判断模型；也没有证据支持直接换成这套 WeSpeaker 后继续沿用当前规则。不同模型的分数尺度不同，不能拿当前 .59 门槛评判替代模型是否合格。

这不证明所有声纹模型都无法处理，也不证明全窗统计聚类无解。它否定的是“单段取干净后，现有一个余弦界限就自然足够”的假设。

## 配套统计聚类对照：拒绝直接移植

进一步复用服务器已有 WeSpeaker、PLDA 和 VBx，以原分割给出的相同上下文 PCM 提取向量。只使用不少于 3 秒的观察；固定已有 Community 配置 `.6 / Fa=.07 / Fb=.8`，不提供人数或身份答案，不扫描参数。三段推理及聚类分别约 6.35、5.73、5.12 秒，均在 CPU 上完成，没有占用或停止其他 GPU 服务。

完整 180 秒输入的聚类人数为 2 / 2 / 2，期望为 2 / 3 / 4。四人片段中，主男性与两位女性的高占比观察都被合进同一簇，另一男性独占另一个簇；这不是编号排列造成的假象。三人片段中，额外人物缺少占比达到 80% 的合格观察，因此其遗漏不能全部归因于后端。观察包含重复上下文，按观察数量统计不代表独立样本数或真实语音覆盖。

这是“替换配套后端”的局部实验，不是官方完整 Community 管线的成绩：沿用了 SDK 分割和拼接取样，也没有实现公开窗口冻结、历史身份绑定或短 query 回填。结果足以否决直接移植，不能外推为官方模型整体不行。

首次输出中的 124.8 秒前缀使用了错误的证据截点：生产首窗实际允许截至 127.5 秒的右上下文。该前缀明确作废，不用于同输入结论；完整三人/四人结果已经满足否决条件，故没有为补齐前缀表格重复推理。

## 后续实施边界

下一候选必须把“确认旧人”“证据不足”“确认新人”分开，并利用未提交窗口里的多段证据判断是否确有新增人物。不能再把一次未通过匹配、query 存在或重复 PCM 的累计时长当作充分建档证据。

候选须先在保存的状态上同时证明：首窗不重复建立主人物、真实第四人随后可建立独立身份、其他人物误认不增加。短回答、旧人返回和单人控制仍须保留。若只把错误改成更多 UNKNOWN，或需要写入参考人数、人工时间边界，立即停止产品实现。

下一阶段先建立与诊断片段隔离的远场开发集，分别校准旧人接受和新人确认，报告新增真人召回、同人重复建档、跨人合并、每人具名覆盖及未知代价。这次三段会议保留为固定问题回归，不用它们反复选门槛。无标注真实录音按 MOSS 流程补辅助标注，争议区间保留待裁定。只有单一余弦规则在该开发集仍不能区分时，才比较质量感知判定或成套声纹后端；不能把当前失败直接转成未经验证的模型替换。

只有产生可通过上述断言的候选，才进入 Harmony/Android 同步修改、状态测试和一轮相关真机验收。当前没有运行代码变更，不重复构建和播放手机，不把 CPU 诊断或模型对照当成交付证据。
