## 范围与不变量

要改变：错误的取样归属、无充分当前身份支持的永久建档、同人重复身份及其对后来真实人物的影响。

必须保持：

- ASR 文字及原始输入不变；真实短回答、换人和重叠仍可表示，不能用增加未知掩盖错误。
- 当前四人能力边界不变；真实新人物不能为避免重复而被全部压成 UNKNOWN。
- 临时身份可修正；已提交窗口、公开角色编号及已输出 final 不回写、不重新编号，不回收已公开档案编号。
- 查询匹配不能直接污染建档中心；相同输入在不同合法分帧和回调延迟下，状态归属及提交语义保持一致。
- SDK 完全端侧离线，MOSS 只做研发标注；last/complete、cancel、资源回收和下一 session 恢复契约不变。
- Harmony 与 Android 的同名逻辑保持一致。现有有限补全及 `speakerInferred` 语义保留。

本轮不混入 ASR 文本精度、ITN/token 对齐、性能调度、发布组包或 Runtime 生命周期重构。相关既有问题继续单列 OPEN，不因身份优化而静默关闭。

## 第一步：重建第一次重复建档的决定

复用已保存的声学窗口、embedding、提交边界与生产状态机，在首次 S4 建档前保存快照；无需再次播放完整录音。分别记录：

- 每个候选的上下文/当前 PCM 区间、独立有效样本量、重叠和 `evidenceKey`；重叠窗口中的同一 PCM 不得累计成多份独立证据。
- 建档前档案及其真实取样来源、top-1/top-2 相似度、聚类顺序、准入条件、创建原因和容量。
- query 对最终文字/角色归属的修正，以及该修正是否改变了已经建立的档案。计分映射另列，不能混入物理身份解释。

代码入口：`SpeakerDiarizationSession.onWindow/commitWindow`、`OnlineSpeakerRegistry.assignBatch/commitKnown/matchQuery` 和 `SpeakerDiarizationGlobalClusterer`；Android 对应 `SpeakerDiarizationSession`、`DiarizationAlgorithms`、`OnlineSpeakerRegistry`。

当前代码以“存在 query embedding”作为额外建档条件之一，建档中心仍来自上下文聚类；后续 query 匹配修改 remap，不撤销既有档案。这是要验证的状态关系，不预先宣布它就是全部根因。

同一状态分叉实验：

| 实验 | 唯一变化 | 要证伪什么 | 停止/转向条件 |
|---|---|---|---|
| A：建档依据 | 保持阈值、聚类、时序，只替换被怀疑的取样归属；参考或 MOSS 掩码仅限诊断 | 重复来自上下文混入另一人或当前证据不支持上下文中心 | 确认单人样本仍重复时，停止把问题仅归为混合取样 |
| B：容量因果 | 在同一快照中仅禁止已证实重复候选消耗名额，再输入相同后续窗口 | 重复占位导致后来真实第四人未知 | 第四人仍无法正确匹配/建档，则容量不是充分解释；不能直接上线“跳过建档” |
| C：中心更新 | 只对比重复 PCM 权重与按来源区间去重的贡献，不改匹配阈值 | 重复上下文权重导致中心被拉偏、形成新身份 | 中心及首次错误决定不变，则不实现权重去重改造 |

每项先输出首个发生差异的窗口、证据和状态决定，再判断是否实施。实验只保留影响该决定所需的前序状态及后续输入，诊断目标完成就停止，不重复长跑。参考辅助的分叉是定位证据，不能成为产品实现或真机验收。

## 第二步：只实施被局部对照证明的修复

首选候选是让建档证据与当前输出身份一致，并区分“无法确认旧人”和“有证据的新人物”：当前 query 的存在本身不能替上下文中心证明身份。具体采用取样修正、建档判定还是中心更新，由第一步首次错误状态决定；不要一次同时修改三处。

若局部实验支持延后额外身份确认，未确认候选留在现有未提交窗口范围内，未知明确可见，不创建不受控的永久候选池，不延长会话结束或窗口提交时间。用户看到的新增身份延迟和短语音 UNKNOWN 必须作为代价一起验收。

已有档案不得在公开提交之后为修复本片段而强并、回收编号或改写旧窗口。同窗两个声道是否属于同一人不能仅凭“当前不重叠”决定；真实不同人物保护用例必须同时通过。

禁止原样重复此前已否决的试验：统一等待 3 秒、直接跳过上下文占位、仅取最长连续片段、放宽聚类/匹配阈值、用相邻窗口重复音频强制关联。它们曾导致其他语料误认增加；只有明确指出原失败状态为何被新修复消除，才可设计新的独立实验。参见 [身份稳定性记录](SPEAKER_IDENTITY_STABILITY_20260916.md)、[额外身份退化记录](SINGLE_SPEAKER_ENROLLMENT_REGRESSION_20260916.md)。

## 第三步：必要时才评价声纹模型能力

如果正确归属、独立且无争议的建档/查询样本仍无法区分人物，再开展模型能力对照：使用不同时间段的同人和不同人样本，不能用被查询片段本身参与中心建档；同时检查短句、声学变化和重叠。单看对历史混合中心的相似度不能作此判断。

仅在独立样本对照证明现有模型无法满足本任务后，才立项比较模型或表示方式，单独核对端侧时延、内存和大小。不能在当前争议片段上调好阈值后用同一片段宣布泛化通过。

## 验收顺序和停止条件

1. **局部红灯到绿灯。** 固定四人片段中，121 秒附近同人不得永久另立身份；实际第四人约 134 秒出现前，不得由重复身份占满四个档案。第四人取得足够真实证据后应有独立且正确的角色，不能仅把重复档案压成未知而结束验收。
2. **相邻不变量。** 固定单人、2/3/4 人控制；短回答、重叠、旧人离开后返回、真实新人、重复上下文和窗口冻结。检查同人分裂、跨人合并、每人具名覆盖及新身份延迟；不能只看角色数或总 DER，也不能把回到正确身份的临时修正计成新增失败。
3. **跨端验证。** Harmony/Android 状态与 SDK 相关测试后，再编译一个 ZH_EN 诊断 HAP。冻结最终运行提交、模型、配置和 HAP/HAR 身份后，对原 PCM 跑一次同条件真机验证及必要的页面检查。分帧/延迟语义用可控测试证明，不用重复长录音碰运气。
4. **真实录音验证。** 对相关无标注客户录音先补 MOSS 辅助标注，单列已确认和待裁定区间；不能用它代替已有人工标注控制。报告临时与最终结果、每个人的归属、UNKNOWN、碎片和时延，以及生命周期/资源限制。

若主样本改善但其他人物误认增加，或只是把错误转成更多未知，候选不能记为修复通过。若单个错误的根因与相邻不变量已被证明，停止额外诊断重放；完整发布矩阵只在合入/交付阶段按仓库门禁执行。

实施每个实验或耗时验证前，记录目标、预计耗时、输入/状态、唯一变化、放弃判据、输出和证据失效条件。当前只有文档变更，复用 `e7a1acef` 的已有二进制证据，不为本计划重建或重跑手机。
