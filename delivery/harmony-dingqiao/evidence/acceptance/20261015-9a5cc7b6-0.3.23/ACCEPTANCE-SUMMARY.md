# Amphion HarmonyOS ASR 0.3.23 组包前验收摘要（9a5cc7b6）

本摘要是组包前证据，不是最终 ZIP 的验收结论。最终 ZIP 的验收报告绑定其自身 SHA-256，另行外置。

本版相对 10-14 的 0.3.22 修订版（`24aae909`）只改三处：两处文本后处理缺陷与一处绑核恢复缺陷。
**识别模型、角色分离算法与所有默认调度参数均未改动。** 改为新版本号而非再发一个 0.3.22，
是因为客户已先后收到两个同名制品，而本版又改了识别文本。

### 三项需要调用方注意的行为变更

1. **连续念出的数字其转写文本会变**：`一二三四五六七八九十` 由 `123 4567 80 ~ 90` 变为
   `12345678910`；`八九十` 由 `80 ~ 90` 变为 `8910`。
2. **日期/金额/小数两侧的空格消失**：`2 . 58万` → `2.58万`，`2026 / 05 / 15` → `2026/05/15`。
   该项影响面大于第 1 项，覆盖所有经 ITN 产出符号的文本。
3. **绑核恢复后 SDK 会忠实执行配置**：若 `cpuIds` 配的是小核，解锁后也会被重新绑回小核。

## 未解决 / 未验证（请勿理解为已修复）

- **锁屏变慢未解决**。干净包实测锁屏期 0.856× / 0.866×，真实缺口 **0.134×**
  （其中角色分离链 0.091×、ASR 主链路自身 0.043×，即关掉角色分离也只到 0.957×）。
  SDK 侧无独立解法；确定有效的规避是屏幕常亮。
  **客户 10-14 报告的 0.80× 系在被 diagnostics 构建污染的包上测得，该污染值实测 ≥0.22× 实时率。**
- **锁屏期仅点亮屏幕不恢复算力域，必须解锁**（实测仅点亮时排空 0.618×，解锁后 1.550×）。
- **停录时若不等排空会丢文本**（实测积压 133 秒时停止、30 秒后拆会话，文本少 15%）。
- **以「十」结尾的数字串其 `textNormalization.spans` 为空**。文本正确，区间失败关闭。
  成因是折叠后上游语法改为逐位记录，而「十」一个汉字要产出两个字符，必然出现宽度为 0 的区间
  被既有校验拒绝；UTF-8 字符中间无法切分。523 秒会议实测未出现该模式。
- **吐字慢主要症状仍在**（最大空档 105 → 72.5 秒，残余归因待客户确认）。本版未改动。
- **角色结果迟到的现场效果未验证**：机制已在 0.3.22 修订版改好并三臂真机验证，客户现场那次
  21.6 秒尚未用新包复测。
- **绑核不是跨机型/跨版本可移植能力**：同为 Mate 80，`cpuIds=[4..11]` 在 6.1.2.329 上
  `affinity-exact result=1`、在 6.1.0.135 上为 `0`。交付文档已写明须逐机型实测并给出兜底值。
- 本批不包含 TTS 模型；目标说话人增强仅保留接口，不包含所需模型，不能启用。
- 本摘要未覆盖 Android 端：补丁 `0032` / `0033` 位于 Android 经 JNI 共用的 `sherpa-onnx/csrc`，
  **Android AAR 未在本轮重建**，两端行为暂不一致。
