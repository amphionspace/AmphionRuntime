# Android 0.3.8 Diagnostics 角色降级：未关闭

正式 Release 的客户句级输出和角色 4 收益成立，按用户指定的客户收益范围交付。TECNO KI8（Android 13）上的 Diagnostics 角色处理及两构建间角色一致性未通过，不能宣称所有构建、设备的角色能力已验收。

## 现场与影响

冻结源码为 `5f622c6d390e2088570c5f9bbdc212f2f702f3a4`。最终 ZIP 中的 Diagnostics APK 回放 168.2 秒客户录音，28 个原句及文字守恒、唯一 last 后 complete 均通过，但两个角色窗口均标为 degraded，确定句只出现角色 1／2，未出现角色 4。累计已提交推理耗时停在 117495 ms，首个窗口在喂入开始后约 133187 ms 返回。原 FAIL 和输入、产物、输出哈希保留在发布证据中。

同一最终 ZIP 的 R8 Release Demo 使用相同 PCM 与会议参数，输出 28 个完整句，与同次正式 SDK 的 ASR final 逐句一致。角色 4 对应已确认的播放声（8.42–15.74 秒）；界面从中间结果转为最终结果，可再次启动。开始记录到完成为 186716 ms，包含启动、喂入和结束处理，未隔离纯结束等待。采样 UI 未观察到降级提示，但未序列化正式窗口 degradedReason，不能据此严格断言无降级。

## 定位状态

三个安装后模型哈希与交付模型一致，排除漏包和旧模型残留。Diagnostics 测试序列化遗漏 degradedReason／degradedMessage，现有数据不能确定是单窗推理超时、调度还是其他原因。`SpeakerDiarizationLocalClient` 的 10000 ms 单窗 watchdog 只是待验证假设；未通过延长超时或修改断言掩盖。

原先把已降级 Diagnostics 的角色标签作为正式 UI 基准的比较 FAIL 已保留；正式界面改用同次 R8 公共 ASR final 检验文字及句界，并独立核验已确认的角色 4。这个修正不能消除两构建的角色差异，也不等于通用身份准确率通过。

这是本次交付暴露的附属问题，尚无同一设备上的旧版本差分，不标为已证明的新版本回退。按用户要求收尾，不扩展算法或增加模型；后续若修复，应先补齐公开降级原因和每窗耗时、watchdog 归属，再做最小状态对照。原用户已确认的其他身份误认、未知和插话限制仍保留。
