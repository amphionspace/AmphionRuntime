# Police 1.4.0 警言警语全量评测与定向优化

六类警言警语共 4,305 条已全部评测。相对 PR #218 首版，严格整句准确率由
84.00% 升至 84.37%；数字格式等价口径由 85.62% 升至 85.97%。20 条字符错误减少，
无新增退化；其中 15 条在数字格式等价口径下由错变对。
这轮是定向修正：留出集仅 3 条 CER 下降，整句准确率与词表内术语命中率均未提高，
不能据此宣称有显著泛化收益。PR 暂不合入，真机验收后续补充。

## 输入、划分与运行范围

- 基线：`5fb61e1f9d66caaa0f92951db2b4f5f1bf740d0d`，即已包含上一轮六条 V6 规则的版本。
- 模型、数据归档身份沿用 [上一轮报告](2026-09-21-police-v1.4.0-v6.md)，本轮不更换模型。
- 对 `current_police_terms*` 六个数据集全量运行，保留所有失败样本，不剔除长句、大段错识或数字格式不一致的样本。
- 复用已有的 210 条同参数 ASR 转写，仅补跑 4,095 条；逐条校验音频 SHA-256。固定同一转写对比增强前后，不是新旧模型 A/B。
- 先固定划分：此前看过的文本全部归开发集；其余按原始参考文本 SHA-256 前八位取模 5，小于 2 归开发集。同一参考文本的不同音色不得跨组。
- 开发集 1,819 条、1,376 种文本；留出集 2,486 条、1,843 种文本。两组文本交集为空；不声称说话人独立，也不声称模型训练未见过这些文本。
- Linux CPU，stock `sherpa-onnx==1.13.1`，modified beam search / 8 paths，单 recognizer 1 thread；16 kHz、20 ms 分帧、endpoint 2.4/1.4/20 秒、结束补 1.2 秒，与上一轮一致。
- 本轮补上两端 SDK 使用的 `WeTextProcessing==1.0.4.1`、`pynini==2.1.6` 与仓库 `weitn-fsts-v2`：逐段 ITN 后拼接，再执行实际 Harmony terms → plate → station → polish。前后使用同一流程，ITN 的收益不计入本轮代码优化。
- 仍是桌面文本流水线回放，未运行 SDK AGC/VAD、标点模型、热词解码或人名模块，不能代替 SDK API/回调、移动端编译与真机验收。

## 改动

1. 在同音映射执行处保留“催促出警人员”的出发含义，避免 normalize 与末段 polish 再次误改；其他已有到场处警纠错保持原行为。
2. 电台数字补齐零、一、二、七、九等普通数字写法，避免 `幺二零`、长号码和混合码段只转换一部分。沿用原有强字/数字锚点门槛，不新增漏字、错号猜补。
3. 新增 8 条受完整词组或城市/区名约束的映射，例如“访谈背心→防弹背心”“事发明理→释法明理”和两个完整地名；另有 5 条仅匹配完整 final 的纠错。未泛化“访谈”“事发”“湿温”等合法单词，也未猜测“他/她”或缺失数字。

候选源码与词典在查看留出结果前固定 SHA-256；留出结果未用于追加规则。

## 全量结果

严格口径沿用 NFKC、统一大小写、忽略空白标点的整句匹配。另列数字格式等价口径：
对参考和输出同样执行固定 ITN，再统一电台数字的确切写法、米/m、分钟/min、货币和日期/时间表示。
不把“栋/动/腰”等误听当作等价，也不补齐号码。该口径脚本及哈希随本轮证据保留；
它与上一轮未执行 ITN 的分层抽样指标不可直接相减。

剩余一条呼号码段及后文存在严重错识，没有用词典补答案。

### 术语指标的边界

数据包有句子真值，但未找到独立的甲方完整目标词清单。本轮冻结基线中的
`term_gazetteer.txt` 与 `PoliceTermsHotwords.PRESET`，统计其中目标词在输出中的词次命中率；
采用参考文本非重叠最长匹配，重复目标词按次数统计。它是**项目词表内指标**，不能充当完整甲方术语验收。

| 数据集 | 词表覆盖句数 / 全量 | 目标词次命中：前 → 后 |
| --- | ---: | ---: |
| 应用名称 | 58 / 62 | 65/67（97.01%）→ 66/67（98.51%） |
| 行业词汇 | 540 / 1,671 | 531/562（94.48%）→ 536/562（95.37%） |
| 新增警言警语 | 80 / 190 | 89/89（100%）→ 89/89（100%） |
| 警务术语正式集 | 2,183 / 2,183 | 4,300/4,352（98.81%）→ 4,300/4,352（98.81%） |

全部词表覆盖 2,898/4,305 条、5,118 个目标词次，命中由 5,032 增至 5,039（98.32% → 98.46%）。
行业词汇的词表覆盖不足，且当前命中率仍低于仓库既有 97% 目标；不得用合计值掩盖该缺口。
行业对话更适合按整句话术字准确率判断；特殊代码单独按完整数字码判断。

## 留出、误改与回归

- 留出 2,486 条：等价整句 84.47% → 84.47%，词表命中 98.26% → 98.26%，CER 1.912% → 1.906%；3 条字符编辑数下降、0 条上升。数字格式变化和剩余大段错误不能解释为整句修复成功。
- 全量增强相对同一 ITN 输入的负收益样本由 6 条降至 5 条；开发集观测到的“催促出警人员”已修复。其他既有负收益仍保留为后续错例，不宣称增强已无误改。
- 新增 57 条共享回归：旧实现 26 个断言失败；新实现 733 条全部通过。覆盖正确目标不变、普通表达不变、完整 final 边界、数字锚点、原有到场处警纠错和末段 polish。另补 Android V1 的出警语境单测。
- 上一轮 4,156 条转写按原流程回放：20 条等价口径字符错误减少，0 条增加，41 条文本变化但编辑数不变。其中 V6 3,773 条改善 15 条、0 条退化；其余 383 条改善 5 条、0 条退化。不把这些重叠样本与本轮 4,305 条相加宣称独立样本规模。
- Android/Harmony 警务资产同步 28 个文件检查通过。Android 构建/单测、Harmony 主机契约与仓库 CI 结果在 PR 中记录；Harmony HAP/HAR 与移动端真机验收仍待补充。
