# PR #218：encoder INT8 候选验收（2026-09-23）

当前候选固定为 **encoder INT8，decoder / joiner FP32**，运行代码与两端测试产物绑定 `52a9169ffa72907cb41942cbbec34bbbf595629e`。**尚不满足合入条件**：TECNO KI8 的冷加载超过既有 2 秒门禁；量化相对 FP32 存在“二档→一档”等关键内容错误，仍是精度阻断项；逐条得失完整列出，不将整体收益写成无损升级。

## 模型与体积

采用动态 QInt8 MatMul 量化，默认逐张量，其中 190 / 344 组权重使用逐通道尺度。选择只使用原权重的重建误差和增量压缩字节，未使用评测答案；其余算子保留原导出类型。配方见 `asr/tools/prepare_police_1_4_int8.py` 与相邻选择清单；重复生成的 SHA-256 一致。decoder、joiner、tokens、BBPE 词表均与原 FP32 来源逐字节一致。

## 安卓冷加载阻断与诊断处置

手机退出系统误触保护、保持屏幕亮且测试进程为 top-app 后，公开 API 的冷准备 / 模型重载 / Runtime 重准备为 **2194 / 2320 / 2305 ms**，均超过 **2000 ms**；准备后创建 235 ms、暖创建 78 ms、Runtime 准备后创建 97 ms。生命周期顺序与 PCM 识别正常，性能门禁为 FAIL。

原先系统误触保护会自动熄屏，相关早期测量保留为非最终性能证据；它不能解释退出保护后的失败。native 阶段观测将主要耗时定位到 encoder `Ort::Session` 构造，模型 mmap 读取约 0.2 ms。线程数/等待空转实验均未证明解决：公共 Runtime 禁止空转后仍为 2297 / 2452 / 2327 ms，已撤回，未增加缓存、绕过卸载、放宽时间阈值或采用临时原型。CPU 采样只用于定位，不作为正式时延测量。

## 本轮独立校验修复
