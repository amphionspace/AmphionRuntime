# 260628 ASR 模型首字延迟与并发压测报告

## 一、问题复述

本次测试要回答的问题不是“哪个模型整体最准确”，而是：在用户明确更重视首字延迟和并发、可接受一定流式准确率损失的前提下，`/home/ubuntu/models/onnx/k2/260628` 新导出的 transducer / CTC 产物，哪一条路线更适合作为低首字服务端配置。

## 二、关键假设

| 假设 | 风险 | 验证方式 |
| --- | --- | --- |
| CTC chunk16 能显著降低首字延迟 | 中 | 与 transducer chunk32 在同并发档对比 first_partial_ms |
| CTC fp32 虽然模型更大，但单流解码成本更低 | 中 | 对比 RTF、final 延迟、GPU 显存增量 |
| 260628 transducer fp16 可直接部署 | 高 | 实际启动服务加载 ONNX |
| CTC chunk16 精度损失可接受 | 中 | 仅做小样本文本 sanity，不作为完整 CER 结论 |

## 六、异常记录

| 异常 | 根因层级 | 现象 | 处理 |
| --- | --- | --- | --- |
| transducer fp16 加载失败 | 模型导出层 | `decoder.fp16.onnx` 报输出类型 `tensor(float16)` 与期望 `tensor(float)` 不一致 | decoder 回退 fp32 后继续验证 |
| transducer fp16 仍加载失败 | 模型导出层 | `encoder.fp16.onnx` 报输出类型 `tensor(float16)` 与期望 `tensor(float)` 不一致 | 判定 260628 transducer fp16 产物当前不可部署 |
| CTC 首次压测服务退出 | 服务适配层 | sherpa 报 `Only transducer models support contextual biasing.` 后进程退出 | 空热词改走无参 `CreateStream()` |

结论：fp16 问题不应在服务端用运行参数绕过，需从导出脚本或 ONNX 图修复。

## 十、推导链

1. 首字延迟的物理下限首先受流式模型 chunk 影响，chunk16 比 chunk32 更有机会降低首字。
2. transducer 的 decoder/joiner 和 modified beam search 会引入额外逐流计算，CTC greedy 路径更短。
3. 本次 transducer fp16 产物不可加载，所以不能把 fp16 作为当前可部署收益计算。
4. CTC chunk16 fp32 在 150 并发下 0 failures，first_p50 与 RTF 均明显优于 transducer fp32。
5. 因此当前可落地的低首字方案应优先选择 CTC chunk16 fp32，而不是等待 transducer fp16。

## 十一、结论与建议

推荐结论：

| 场景 | 推荐 |
| --- | --- |
| 低首字优先 | 使用 `ctc-chunk16-lc128` + `greedy_search` + `fp32` |
| 精度优先 | 继续使用 transducer chunk32 fp32 |
| 兼顾首字与显存 | 让训练/导出侧补可加载的 CTC chunk16 fp16 |
| transducer fp16 | 当前不推荐上线，需先修复 ONNX 类型错误 |

建议默认启动参数：

```bash
MANIFEST=/home/ubuntu/models/onnx/k2/260628/ctc-chunk16-lc128/manifest.server.json \
PROVIDER=cuda \
ENCODER_PRECISION=fp32 \
DECODING_METHOD=greedy_search \
DECODE_WORKERS=2 \
MAX_BATCH_SIZE=130 \
MAX_CONCURRENT_SESSIONS=220 \
LOOP_INTERVAL_MS=5 \
./asr/server/run_server.sh
```
