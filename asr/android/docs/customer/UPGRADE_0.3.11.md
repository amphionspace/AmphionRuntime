# Android ASR SDK 0.3.11 升级说明

本版相对 0.3.10 是**行为修复版**：识别模型、热词、公共接口与回调顺序不变，无破坏性变更。
修复对应客户工单 #100、#92（第二轮）、#29、#97、#35；其中 #92 / #29 / #35 与 HarmonyOS 0.3.30 同修，
#97 补齐 HarmonyOS 0.3.29 的修法。

运行时版本为 0.3.11，版本日期为 2026-11-19；商用授权的维护期限须覆盖该日期。

---

## 一、机主 → 非机主 → 机主时，机主第二次发言丢失（#100）

### 1.1 现象

实时语音转文字开机主识别，机主说完、非机主接着说、机主再说时，机主的第二句没有输出。

### 1.2 原因

两处都是 HarmonyOS 0.3.28 / 0.3.29 已修、Android 未同步的同名逻辑：

- 换人切分后为后缀置上的"离场后待确认"标志只在"发布机主句子之后"清除，而该标志又让当前句恒被拒绝，形成死锁：后缀被拒一次后，机主再说话无论声纹分多高都被拒。
- 仅开机主识别时，非机主连续说话不切句，非机主与机主并成一句，整句声纹分被稀释后整句被拒。

### 1.3 本版改法

- 一句话结束 / 识别流重建时清除该标志，重放的后缀按新证据重新打分，非机主仍被拒；
- 非机主连续说话时每约 1.5 秒切一句并拒绝，机主回来起新句；切句与"离场"都要求该窗口带 VAD 语音，静音不再触发（短指令说完后的静音不会把这句切掉）。

客户录音在鼎桥安卓机复测：机主两句均发布（0.722 / 0.754），非机主 23 秒被切成 11 句全部拒绝（最高 0.282）。

**已知限制**：机主紧接非机主开口时，机主这句句首会带上非机主最后约 1.5 秒的字，这是流式打分延迟的固有泄露；长句切分后前缀重解码耗时较长（19 秒前缀约 12 秒），机主句子的回调时延另立跟踪项。

## 二、机主 PTT 短指令"OKOK"被判非机主（#97）

Android 此前只有整文件多模板，1 秒级短指令的声纹分对 0.35 门限余量只有 0.02。本版注册时每份样本另切 2 秒分段模板随声纹档案保存，句末判定对"整文件 + 分段模板"取最大；流式确认与换人边界校验仍只用整文件模板。

- 同一段客户录音：0.370 → 0.444，正常转写"OK O。"
- **需要重新注册一次机主声纹才生效**；旧档案没有分段模板时按原行为运行。
- 建议注册时补一份按 PTT 使用姿势录制的近讲样本，或把指令说到 1.5 秒以上。

## 三、静音 / 底噪里反复转写出"嗯"（#92 第二轮）

此前的发布门禁只在开机主识别或 Speaker VAD 时才被喂音频，普通转写场景实际没有生效。本版门禁无条件喂音频；只由填充词（嗯 / 呃 / 啊 / 哦 … ≤4 字，或 um / uh / hmm）构成、且本句原生 VAD 从未判出语音的句子不发布。真人说的"嗯"照常发布，含实词的文本不受影响。鼎桥安卓机复测四档底噪 0 条填充词，真人"喂 / 嗯"保留。

## 四、角色分离：角色编号与归属（#29）、`speakerCount`（#35）

- 分割轨道开身份前必须有识别 token 证据，开头的按键 / 环境声不再领走"角色1"的编号；文本经数字规范化对不回 token 时，整句只有一个已知角色就归属该角色。客户录音复测 A / B / C = 角色 1 / 2 / 3，含号码句归角色 1；客户会议录音回归 DER 5.66% 不变、角色混淆 0.9% → 0.0%。
- 开启声纹身份时 `speakerCount` 数声纹身份数，单人不再报 2。

## 五、调用方需要做什么

1. 替换 `aar/dingqiao-asr-v0.3.11.aar`，重新编译安装；
2. 机主识别场景：引导机主重新注册一次声纹，以获得分段模板；
3. 客户 App 落盘的注册样本若长于 8 秒，`registerVoiceprint` 会以 `VOICEPRINT_SAMPLE_DURATION` 拒绝，请把样本控制在 8 秒内。

## 六、回退

0.3.11 无数据格式或接口变更，回退到 0.3.10 只需换回旧 AAR 并重新编译。新注册产生的 `segment-templates.bin` 会被旧版本忽略。
