# Android ASR SDK 0.3.12 升级说明

本版相对 0.3.11 是**行为修复版**：识别模型、热词、公共接口与回调顺序不变，无破坏性变更。
修复对应客户工单 #102（并覆盖 #100 的遗留项）。本版只改 Android，HarmonyOS 端无对应改动（鸿蒙同一处逻辑原本就是本版的口径）。

运行时版本为 0.3.12，版本日期为 2026-11-27；商用授权的维护期限须覆盖该日期。

## 一、机主识别：非机主语音漏出并与机主第二句并句（#102）

### 1.1 现象

实时语音转文字开机主识别，按"机主 → 非机主 → 机主"说话：非机主中间一段话被当作机主发布；非机主最后一句和机主的第二句并成一句一起发布。

### 1.2 原因

两处都只在 Android 存在：

- 鼎桥封装层把机主阈值设为 −1（只打分、不在 SDK 内丢弃）。流式判定一旦被非机主的某一个 1.5 秒窗口（打到 0.39，高于 0.35）误判为"机主回来了"，句级门限就跟着退化为 −1，随后相似度只有 0.29 的非机主片段也原样发布。HarmonyOS 同一处一直用 0.35 的业务阈值。
- 换人切分只在"机主 → 非机主"方向进行。非机主说完、机主在静音判停时长（客户 1600 ms）内接话时，两人并成一句，整句相似度被机主抬到 0.83，非机主的尾巴随之发布。

### 1.3 本版改法

- 句级门限改为"调用方阈值与 `speakerVadThreshold`（默认 0.35）取较大者"，与 HarmonyOS 一致。
- 新增"非机主 → 机主"到达侧切分：机主刚被确认、且这句确认之前已有带语音的低分窗口时，在两人交接的停顿处（≥0.25 秒静音）切开，前面部分按非机主拒绝（走 `onFinalRejected`），后面部分作为机主新句继续。只在本会话已出现过机主发言后启用，会话开头的短指令行为不变。

客户录音在鼎桥安卓机复测（仅机主识别 / Speaker VAD 两种模式一致）：机主两句均发布（0.78 / 0.83），非机主 5 段全部拒绝（含原漏出的 0.29 片段）。
#100 客户录音回归通过，且 0.3.11 说明里记录的"机主第二句句首带非机主约 1.5 秒的字"这一限制也随本版消除。

### 1.4 已知限制

#102 录音里非机主最后约 1.2 秒"主路开走了"仍随机主第二句发布：这一段单独对机主声纹打分 0.506，机主自己的起头只有 0.583，两人之间停顿约 0.12 秒，当前声纹模型无法区分。若现场要求更严，可按部署把 `speakerVadThreshold` 提到 0.5~0.55，代价是机主短句（历史最低 0.525）更容易被拒，请在目标机型上评估后再调。

## 二、调用方需要做什么

1. 替换 `aar/dingqiao-asr-v0.3.12.aar`，重新编译安装；无需改任何调用参数。
2. 展示文本请取最终结果（`onFinal` / 结果回调的 final 文本）；中间结果不做数字规范化，电话号码会显示为"幺三八…"。
3. 机主识别场景沿用 0.3.11 的建议：注册样本控制在 8 秒内，并补一份按使用姿势录制的近讲样本。

## 三、回退

0.3.12 无数据格式或接口变更，回退到 0.3.11 只需换回旧 AAR 并重新编译。
