# Android ASR SDK 0.3.9 候选升级说明

本包为待验收候选，禁止分发。角色分离仍有漏人、误认及短段 UNKNOWN；合入不等于正式交付通过。

相对 2026-09-18 双端基线：修正证据、文本和时间区间归属，保留未提交身份可修正及已提交窗口冻结。

**本版角色分离已整体更换为 Sortformer，下面第三节单独说明。** 原 Community-1 链路（pyannote
分割 + WeSpeaker 嵌入 + PLDA/VBx 聚类）已整体移除、不保留后备，因此"两端整窗聚类路径不同"
这一历史差异不再存在：Android 与 Harmony 现在共用同一份角色分离实现。

## 角色分离整体更换为 Sortformer

原链路（分割 + 声纹嵌入 + 聚类三段式）整体移除，换成一个端到端流式模型，**不保留后备**。
与 HarmonyOS 0.3.26 是同一个模型、同一份实现，两端角色结果自此一致。

同机、同音频、同评分口径（openbench-der-v1：collar 0、计入重叠、Hungarian、UEM 受限）：

| 录音 | **本版 Sortformer** |
|---|---:|
| 100350-257 | **3.01%** |
| 102010-230 | **13.56%** |
| 111223-816 | **26.24%** |
| recording-a | **6.41%** |
| **全集** | **12.10%** |

与 HarmonyOS 0.3.26 同口径同录音的 12.10% 一致，逐条最大差 0.06 个百分点。

原三段式链路在同一评分口径下的全集 DER 为 24.89%。该数字来自宿主侧的近似对照臂
（pyannote + ERes2Net + FastClustering，与 Sortformer 的 4 槽位对等），**不是**在手机上跑
旧产品链路测得的，逐条不作对比。

**调用方要知道的三件事**

说话人上限仍是 4，但四个槽位现在是**模型自己按到达顺序**给的身份，整个会话稳定，不再有聚类
造成的中途改号。`speakerIndex = -1` 仍表示未定归属：只在预览里出现过、所属块还没提交的说话人
保持 -1，提交后才成为正式角色。

结束到最终角色结果的时延变长：块提交周期是 9.92 秒，短于该长度的会话只会在收尾拿到一次结果。

一加 PHK110 实测角色分离推理 RTF 0.120。这是单台设备的实测值，不同 SoC 差异会很大。

**两条必须一并知悉的限制**

第一，**上面的 DER 是 UEM 受限口径**。这四条录音的参考是局部听审标注、总计 78.542 秒，而音频
总长约 900 秒，评分只在标注范围内进行。该数字用于版本间和两端对比是有效的，**不能当作整体
准确率**。

第二，**长会议中段可能出现成片没有角色输出**。四条录音里两条存在这种区间，最长一段 136.8 秒，
而那些区间里有人在说话。该现象在 HarmonyOS 0.3.26 上同样存在，不是本版引入，根源在两端共用的
实现层，我方已单独立项排查。受上面第一条限制，这个现象不会反映在 DER 数字上。

## 本版修掉的两个现场问题

**一、热词不再吞掉后续文字。** 热词表含「遣返」时，手机号首位曾被改写成「遣」，其后整段数字
被删。成因有两处：多字热词的首字与整条热词同权重，在还没有任何证据表明后续字会出现时就能压掉
同音字；停在半匹配上的解码路径保留着加分，而退还只在吐出非空字符时结算，于是它可以持续输出
静音仍压住真实数字。本版给多字热词首字加分封顶 1.0，并让半匹配前缀连续 1 秒空白即强制失效。

主机 500 条热词语料回归（逐词 3.0 + 警务预置池）：整体字错率 1.021% → 1.075%，热词召回
97.25% → 97.09%，619 个热词实例少命中 1 个。真机 7 例客户录音夹具全部正确，含贵方原样 53 词表。
**公开接口与热词入参格式不变，预置池 1.0 与单字热词行为不变。**

**二、机主停止说话瞬间非机主接上，非机主首句不再被录入机主。** 真机 6 例「机主一段后无间隙接
另一人 1.4~1.6 秒」，修复前 4 例把非机主的话录成机主的，修复后 6 例全部拦住。两处成因：换人点
定不出来时收尾兜底会直接退出而放行已知混合的整句；以及换人后的短尾音声纹分落在 0.35~0.52 这条
实测空带里（机主自己短句最低 0.525，非机主最高 0.459），只按默认阈值 0.35 判不出来。本版在
定不出换人点时退机主的保守前缀，并把收尾切片与未经流式确认的句子按实测下沿 0.45 判。

**代价请一并知悉**：机主句尾可能被保守切点截掉一两个字。另外这条下沿的测量用的是同一会话内的
注册音，机主一侧偏乐观；**跨会话注册（贵方真实场景：声纹是另一天录的）下机主短句会不会被误拒，
我方尚未验证**，需要贵方提供真实声纹加一段机主短句复测。

**回调契约不变**：被判为非机主的那一段仍发空 final，非机主文字不进调用方。

调用方按 windowIndex 累积角色结果，以 sourceUtteranceId 关联原 ASR 句子；临时身份允许修正，角色末批使用 isSessionFinal。isFinal 仍指 ASR 句末，isLast 仅指 session 最后一条，不能混用。保留 UNKNOWN、overlap、speakerInferred 和原始 speakerTurns，不按逐字角色变化拆坏完整词语。
