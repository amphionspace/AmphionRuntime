# Android ASR SDK 0.3.6 升级说明

相对上一交付 0.3.5，本版更新离线角色分离的建档、最终身份匹配和文字边界处理。模型、最多 4 人的能力范围及 ASR 生命周期契约保持不变。最终交付状态以本版本完整 ZIP 对应的外置验收报告为准。

## 更新内容

- 优先为音量较大的主讲人保留身份名额，减少较轻背景声音占位。相对音量过滤也可能使轻声主讲人返回 UNKNOWN；它不能判断声音是否来自背景。
- 最终定稿保留有真实取样支持的身份，修复已验证双人录音中两处主要发言串人。该结论不延伸到所有短插话及重叠发言。
- 短暂未知、声学空隙及副角色变化不再直接拆坏词语。有限的同句 UNKNOWN 邻接补全使用 `speakerInferred=true`、`confidence=0`；原始 `speakerTurns` 仍保留未知及重叠信息。

## 接入重点

1. `speakerInferred=true` 是根据同句相邻证据推断的文字归属，不是确定的声纹识别；不要把 `confidence=0` 改成已确认分数。
2. 继续按 `windowIndex` 累积角色结果，用 `sourceUtteranceId` 关联原句。临时结果允许修正，已提交窗口保持冻结；`isSessionFinal` 表示角色末批。
3. `isFinal` 表示 ASR 原句结束，`isLast` 表示 session 最后一条 ASR 结果，均不能代替角色定稿标志。继续使用 session 输入时间轴，不叠加前句时长。

## 验收范围与交付阻断

当前修复证据覆盖客户录音中四位较响主讲人的主要发言及双人录音的指定主要换人。轻声/背景允许 UNKNOWN；用户已明确暂缓短插话修复。现有短插话误认、部分文字归属与声学时间线不一致、四人重叠控制误认仍未解决，因此通用角色身份精度不能判为可交付。需要这些场景的业务应保持该能力停用，待对应体验用例通过。

Android 锁屏/后台角色处理的既有失败仍未解决，当前版本未新增修复。没有本版本最终 ZIP 真机报告时，不得沿用 0.3.5 或鸿蒙测试宣称 Android 验收通过。

目标说话人增强仍缺少所需模型，不能启用。Diagnostics 会采集 PCM 和文字，只用于获授权的问题定位；正式业务使用 Release AAR。
