# ASR 产品与公共契约

路径均相对仓库根目录；本文件由根 AGENTS.md 按任务引用，所列约束仍须遵守。

## 用户体验与角色分离

- 验收首先回答用户能否读懂、能否信任和使用结果。ASR 与角色分离的目标是：句子可读、真实换人可区分、不确定时诚实表达、定稿后结果稳定可信。接口成功、文字守恒、生命周期正确、性能或聚合精度指标通过，都不能单独证明产品可用。
- 分别报告接口契约、识别及身份精度、用户可见体验的结论。任一核心体验用例失败，相关能力就不能判为验收通过；已知的身份误认或不可读结果必须成为该能力的交付阻断项，不能只留在报告的“已知限制”中，同时宣称已解决或可用。
- 把用户症状写成可失败的验收用例。没有真实换人证据却把“你好”拆成“你 / 好”、把“张三”拆成“张 / 三”、同人发言被错误地反复换号，均属于体验失败。真实的单字回答、短插话和换人必须保留，不能用统一最短字数或时长门槛消灭所有短段。
- 文本段落边界不能机械跟随每个 token 的角色标签。UNKNOWN、短暂声学覆盖空隙及副角色/重叠标签变化，本身不构成主说话人换人的证据；应保留其不确定性和时间区间，避免将其直接放大成可见的单字碎片。不得拆坏完整词语来证明角色切分功能有效。
- 角色临时结果须明确可修正；停止后尚未完成角色定稿时须明确处理状态。最终标签必须与 SDK 已提交结果一致，已提交窗口保持冻结。允许有证据的临时纠错，不能仅以编号切换次数判断失败，也不能把临时角色当成最终身份交付。
- 不得为改善观感而伪造确定性：不能按多数角色覆盖整句、复制前一句身份、强行归并不同人物、吞掉未知或重叠信息。按 `sourceUtteranceId` 合并展示只能作为可读性缓解；误认仍在时，不得称为身份精度修复。UNKNOWN 减少、段数减少也不能替代正确性证明。
- 用户明确允许有限的 UNKNOWN 邻接补全：同一原句内，首尾只有一个相邻已知角色，或前后已知角色相同，且未知段不超过 2500 ms、原时间线没有相反的已知角色证据时，可以补全并合并文字。已知副角色或来源不明的 overlap 必须阻止补全；仅 UNKNOWN 副角色可保留重叠标记后做推断。句尾零时长 token 还须在 2500 ms 内有相邻角色的真实声学支持，不得仅沿用旧段落标签。必须标记 `speakerInferred=true`、将该文本段 `confidence` 置 0、保留原始 `speakerTurns`；不能跨句传播、串联推断结果继续扩散，或把补全当成声学身份精度修复。边界依据与对照见 `delivery/harmony-dingqiao/docs/UNKNOWN_SPEAKER_BACKFILL.md`。
- 相关改动必须同时检查 SDK 公共原句、角色时间区间和真实调用方最终呈现，定位体验在哪一层首次偏离。针对原始失败样例验证可读性，并用必要的单人、多人真实换人、短插话、未知及重叠场景保护相邻行为；身份精度使用人数已确认且不超过能力范围的标注录音，分别报告误认与未知。没有客户原音或标注时，明确同类复现的范围，不将替代语料写成客户原会话已经通过。
- 修复完成的条件是原始体验失败用例转绿、必要的相邻精度与生命周期检查通过，并且没有已知的相关退化。不能以“单测全绿”“回调正常”或“指标改善”替代结案。复用同提交、同产物的有效证据，不为新增验收措辞重复长跑；新的体验断言只补最小必要验证。
- 真实录音没有标注时，先用 `amphion-42:~/workspace/audiollm-go` 的 MOSS-Transcribe-Diarize 做独立辅助标注，再定位识别和角色问题；具体流程见 `delivery/harmony-dingqiao/docs/MOSS_ANNOTATION_WORKFLOW.md`。MOSS 只接收音频，不预先提供期望人数、SDK 标签或答案；保留原始输出、模型/输入哈希、时间偏移、截断与分歧记录。辅助标注不是人工真值，争议、重叠和特殊发声区间须单独标记，未裁定不得用于确定性根因或正式精度结论。评估器的一一编号映射不代表建档音频的真实身份，必须回溯取样证据后才能区分误认、同人重复建档和模型能力问题。MOSS 仅用于研发标注，不接入端侧 SDK 推理链路。

## 生命周期

- `isFinal=true` 表示一句话或一个 endpoint 的最终结果；`isLast=true` 只表示整个 session 的最后一条结果。不要把二者混用。
- 普通连续识别中，调用方执行 `finish(sessionId)` 之前不得出现 `isLast=true`。仅显式配置并命中 `vadBegin` 或 `maxAudioDuration` 时允许 SDK 自动结束。
- 每个正常结束的 session 必须恰好产生一次 `isLast=true`，之后恰好产生一次 `onComplete`；`cancel` 不得产生 final 或 complete。
- 每次自动结束都必须能归因到明确的终止条件。排查提前结束时，先记录 `finish` 调用、`vadBegin`、`maxAudioDuration`、写入 PCM 时长和完整回调时间线，不要先猜测模型问题。
- 初始起音属于多信号状态：VAD 或 ASR 的非空 text/token 任一确认语音后，必须永久解除本 session 的 `vadBegin`。声学 backstop 不能把“高于固定音量”直接等同于 speech：它只能先触发一次有界确认；持续活动还要满足语音型能量变化和过零率范围，才可解除计时，且不得伪造 speech 事件。
- 组合参数必须按能力的时间前置条件验收。启用声纹校验或 Speaker VAD 时，`vadBegin` 本身仍是纯静音等待；只有显式配置正数 `TargetSpeakerConfig.minSegSec` 时，初始等待窗内连续但未决的声学活动才允许获得不超过该值的一次性确认窗。默认 `minSegSec=0`，不延长等待。旧活动不能在确认窗末直接解除计时：必须仍有近期语音型活动，或强制刷新 ASR 得到非空 text/token。测试必须分别验证纯静音、稳态高能非语音、零散脉冲和真实语音，不能只检查参数解析。
- 异步回调只能根据当前结果携带的 `isLast` 决定是否完成会话；不得用全局 `finishRequested` 推断某条较早结果是最后一条。
- `onStart` 是会话已经可用的承诺，不只是底层 native 构造完成通知。SDK 对外回调前必须已经发布 session 并完成会话级配置；调用方允许在 `onStart` 内同步执行 `writeAudio`、`finish` 或 `cancel`，不得收到 `NOT_LISTENING`。
- 进程级 `unloadModel` / Runtime release 不得越过活跃 session 的 native 异步工作。session 只有在公开回调关闭、最后一个 in-flight native 调用返回且 stream 已关闭后才算 quiescent；释放等待期间不得创建新 session。重新设置授权触发 Runtime 替换时也必须遵守同一边界。

## 声纹结果

- 公共字段名是 `speakerSimilarity`。新增或修改示例、文档和测试时必须使用该名称。
- SDK 的职责是对已确认的语音产出声纹结果，业务方负责根据使用场景选择阈值并承担短句精度风险。
  `TargetSpeakerConfig.minSegSec` 默认且在鼎桥适配层固定为 `0`，SDK 不设置最短时长门槛；ASR 已产生
  非空 text/token 时，必须使用本句非空真实 PCM 尝试评分，不得仅因时长或内部质量判断省略分数。
  业务方自行根据音频时长、相似度和场景阈值决定是否采用。没有 ASR 语音证据、没有真实 PCM、
  声纹能力未启用、有效 ID 缺失或
  extractor 在技术上无法产生 embedding 时可以省略；不得填充假分数、复制上一句分数或补静音。
- 排查 `speakerSimilarity=undefined` 时，必须同时记录 `enableVoiceprintVerification`、`enableSpeakerVad`、`voiceprintIds` 数量、调用方传入和 SDK 生效后的 `vadBegin`、实际写入 PCM 时长以及该 final 的有效语音时长。缺少声纹开关或有效 ID 时不得归因为打分异常。
- 声纹测试至少覆盖：`minSegSec=0`、500 ms 短句、自定义正数门槛的边界、低音量、前置静音、非注册语料源和多句连续输入。有真实 PCM 的每个非空 final 都必须逐条核对分数，不能用“整轮至少一个分数”代替。生命周期门禁只判断出分资格、回调顺序和会话恢复；目标/非目标相似度精度及短句风险另走带身份标注的评测集，由业务方决定阈值和接受策略。
- 同时启用声纹校验和 Speaker VAD 时，必须区分 native stream 边界与公开 final 边界。token-only endpoint 被抑制时可以清理 Speaker VAD 当前流窗口，但不得丢弃声纹回退 PCM；测试至少覆盖两个各短于门槛、合并后达到门槛的 native segment。

## 离线能力

- 鼎桥识别、声纹、Speaker VAD 和角色分离必须在端侧离线运行，不得上传 PCM、文本或 embedding，不得要求调用方配置服务地址。
- 当前角色分离已采用本地推理；历史服务化实现不是当前公共配置。实现已离线不等于发布验收通过，发布仍须提供断网公共 SDK 功能、生命周期及无运行时网络请求的证据。

## 特定客户场景

仅处理该场景时适用，不作为所有录音的通用规则：

- 2026-09-17 客户会议当前修复范围按用户明确要求，先保证四位音量较大的主讲人；轻声/背景允许 UNKNOWN，但不得占用这四人的名额。不能继续以保护轻声召回为由阻挡这一轮；也不能把这一取舍宣称为通用背景识别、所有音量均通过或强制每段录音四人。当前 CPU 路线不得再运行或移植 Sortformer。范围、代价及验收见 `delivery/harmony-dingqiao/docs/CUSTOMER_MEETING_MOSS_AUDIT_20260917.md`。
