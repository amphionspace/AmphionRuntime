# 修改版程序复测结果汇总（2026-08-19）

## 1. 测试目的

本报告汇总修改版 Amphion HarmonyOS 离线 ASR 程序的两项真机复测：

1. 使用长会议 WAV 检查快速批量送入 PCM 时，SDK 是否卡死，以及是否存在“有语音输入但完全没有文字输出”的片段。
2. 使用《阿长与〈山海经〉》MP3 检查中间结果转最终结果时的边界文字丢失是否改善。

测试分支为 `codex/fix-harmony-offline-long-audio`，核心程序提交为：

```text
0acd153 fix(harmony): bound offline audio queue and preserve ASR boundaries
```

修改版程序采用有界异步音频队列和背压，通过 `writeAudioAsync()` 快速送入 PCM；连续语音强制端点由约 20 秒调整为 55 秒，并在端点切换时保留跨边界 PCM。

### 2.4 长会议结论

1. 修改后的有界队列能够处理完整长音频，没有复现快速投帧导致的识别卡死。

## 4. 综合结论

修改版程序解决了快速批量送入长音频时的队列失控和识别卡死问题，长会议测试中所有实际 utterance 均产生了非空最终结果；同时，把连续语音强制端点从约 20 秒调整到 55 秒后，边界遗漏字符由 105 个降到 37 个，改善稳定且可重复。

当前仍有两个后续问题：一是低语音占比或超长 utterance 的首条文字延迟可能达到分钟级；二是边界遗漏尚未完全消除，剩余错误需要从模型解码、端点判定及跨端点上下文保留三个方向继续分析。
