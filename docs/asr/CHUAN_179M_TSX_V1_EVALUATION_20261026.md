## 四、为什么 CER 口径会低估警务损失

| 口径 | 测试集 | 变化 |
| --- | --- | --- |
| 厂商 CER | `police_terms_v5_test`（64 条） | 1.89 → 2.12，**退 0.23 点** |
| 我们 KWR | 警言警语 V6 官方术语表（621 条） | 72.3% → 66.67%，**退 5.63 点** |

相差约 **24 倍**。机制：CER 把错字平摊到全句，KWR 判定**术语是否完整命中** —— 
术语错一个字，CER 只涨零点几，KWR 直接记为未命中。抽样可见得失互相抵消：

| 参考术语 | 现产 | 候选 |
| --- | --- | --- |
| 情指行平台 | 引指形平坦 ❌ | **引指行平台** ✅ |
| 签收警单 | **签收警单** ✅ | 前所进单 ❌ |
| 视频清整 | 视频清整啊 | 视频清整啊 |

**结论：警务项目的模型提测不应以 CER 作为验收口径**，须同时给出 KWR（术语整串命中）。
建议写入提测规范。

### 5.1 功耗说明

**绝对功耗（mW）在当前条件下测不了。** 鸿蒙真机电池遥测：

```
voltage:        4437568 µV = 4.44 V
nowCurrent:     -1          ← 不可用
chargingStatus: 3（满电）     pluggedType: 2（USB）
temperature:    260 = 26.0 °C
```

设备 USB 连接且电量 100%，`nowCurrent` 不可用；而 hdc 调试必须 USB 连接，
故有线条件下绝对功耗在原理上不可测。仓库既有结论一致
（`DIARIZATION_BRANCH_HEAT_20261007.md`：插 USB 且亮屏时各组 16 分钟都升 9–11 °C，组间无可测差别）。

要取绝对功耗需：① 拔 USB + 无线 hdc；② 外接功率计。

本次采用 **CPU 秒/音频秒** 作为功耗代理 —— 能耗 ∝ CPU 时间，同平台同架构下两模型的
CPU 时间比值即能耗比值。实测 0.12 vs 0.13，**功耗无实质变化**。

### 5.2 尾包时延（顺带补齐客户指标表第 76 行）

本次首次实测 ASR 尾包时延：现产中位 27.7 ms / P95 31.16 ms，
候选中位 30.0 ms / P95 33.68 ms。
客户指标表该项此前一直为「无实测、推测 ≈250~300ms」，现可填入实测值。
注：此为宿主侧 `input_finished` → 最后一次 decode 完成的耗时，不含音频前端与回调分发。

## 六、交付侧风险

### 6.1 候选是 ONNX，现产部署件是 ORT

候选包提供 `.onnx`；现产端侧部署件为 `.ort`（经 `onnxruntime-1.24.3-fixed-arm-cpu-v1` 转换）。
按 `MODEL_LOAD_PERFORMANCE.md`：**ONNX 冷加载约 2.6 s，ORT 约 730 ms（3.5 倍差）**。

本次 A/B 两侧均用 `.onnx`，保证公平；但**上线前必须补「候选 ONNX→ORT 转换后复测」**，
因转换带全图优化，可能影响数值。交付脚本会做转换，但提测阶段无人验证过转换后精度。

### 6.2 pinned MD5 校验

交付脚本含 `pinned Dingqiao ZH_EN ONNX MD5 verified` 检查。换模型需同步更新 pinned 值，
否则打包会失败。

### 6.3 未覆盖的维度

| 项 | 未测原因 |
| --- | --- |
| ~~真实四川话~~ | **已补测**：数据在 SenseCore AOSS `whai:audio-data/datasets/`（241 个数据集），非 COS 评测桶 |
| 噪声分档 A/B | 本轮未对候选做 babble/traffic × 4 档加噪（可补，约 40 分钟）|
| 热词干扰（同音过触发）| 候选 beam 动态变化，「热词致裸数字串整句塌陷」门槛需复核 |
| 真机端侧实测 | 需转 ORT 并构建 HAP/APK；安卓真机当前断开 |
| server-ctc 包 | 592 MB CTC 模型，非端侧 transducer 路径，未测 |
