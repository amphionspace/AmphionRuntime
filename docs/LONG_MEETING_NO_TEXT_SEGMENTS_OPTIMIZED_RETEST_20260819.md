1. **严格无文字片段**：完整 utterance 内存在 Silero VAD 有声窗口，但从开始到结束没有任何非空 partial 或 final。

## 6. 新指标给出的定位结论

本轮 62 个非空 public utterance 总计跨越 853 个 native segment，其中 791 个 native endpoint 没有发布为公共 final。两者相减正好为 62，说明每个非空 public utterance 最终由一个有文字的 native segment 发布，前面的空/tokenless segment 被聚合抑制。

EOF 终止阶段另有 4 个 native segment：前 3 个空段被抑制，最后一个 `reason=finish` 的空段发布为 `isLast` 生命周期结果。因此完整 session 合计为 857 个 native segment、794 次抑制和 63 次发布，其中只有 62 次包含文字。

最严重的 utterance 38 并不是 sherpa-onnx 连续 623.52 秒没有 endpoint。它内部实际出现 244 个 native segment，其中 243 个没有可发布文字而被抑制；从现场日志看，大量空 segment 的 PCM 时长约为 2.56 秒。真正的问题是：

```text
底层持续 endpoint -> segment 没有 text/token -> 公共层抑制并继续累计
-> 直到后续 segment 有文字才发布 public partial/final
```

因此，本轮可排除“底层 decode 或 endpoint 完全卡死”。当前主要问题收敛为低语音占比/弱语音条件下，连续多个 native segment 无 token，公共层又没有面向用户的进度或空段边界通知，导致有声输入长期没有可见文字。

## 8. TEXT 原文字段发现的新问题

本轮每条 TEXT 已包含 `sessionId`、`text` 和 `textHex`，但检查 `result.txt` 原始字节发现，`text=` 当前按 UTF-16 code unit 的低 8 位写入。例如“`一二`”的 `textHex` 正确为 `4e004e8c`，而 `text=` 落盘字节为 `00 0c`，会产生 NUL/控制字符并破坏普通行解析。

因此当前证据可靠性为：

- `sessionId`：可靠；
- `textHex`：可靠，可无歧义复原全文；
- `text=`：字段存在但编码错误，尚不能满足“可直接读取的原始文本”要求。

本报告使用 `textHex` 作为文字权威来源，并通过跨行解析恢复全部 604 条 TEXT 记录。后续应修复 App 的文本文件 UTF-8 编码写入，再增加包含中文、竖线、反斜线、回车和换行的真机证据门禁。

## 9. 结论

1. 本轮没有任何“完整有声 utterance 从开始到结束完全没有文字”的片段，严格数量为 0。
2. 仍有 13 个“存在语音但至少 5 秒看不到文字”的片段，音频范围见第 4 节，数量没有改善。
3. 最严重片段仍是 `24:59.540–35:23.060`，首条文字等待 145.552 秒；虽然比上轮少 4.913 秒，但问题仍然严重。
4. 新指标确认该段内部发生了 244 次 native segment，243 次被抑制；问题不是底层 endpoint 卡死，而是连续空/tokenless segment 无法形成公共文字输出。
5. 修改显著改善内存：峰值 RSS 下降 81.594 MiB，RSS 首尾增长从 67.990 MiB 降到 12.465 MiB；队列峰值保持在 512 KiB 高水位以内。
6. public 识别全文与上轮完全相同，因此本轮优化没有改善或破坏识别文字质量，主要价值是内存有界和根因可观测。
