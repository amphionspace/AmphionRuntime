# run 策略 UNKNOWN 的帧级归因（2026-09-28）

**结论：按事先冻结的判据，195.40 秒"检测到但无身份"中，没有任何一类能在不增加误认的前提下恢复。** 逐类只把 UNKNOWN 帧换成整窗路径给的身份后，误认率在 10.5%–61.6% 之间，门槛为 1.3%。一次替换全部 UNKNOWN 帧：找回 194.69 秒，同时新增误认 22.19 秒、误报 19.99 秒，同一参考人的换号在 4/6 段增加（AISHELL-4 四人片由 2 次增至 11 次）。原先预计的首个候选——overlap 帧继承同通道一致身份——预演误认率为 18.6%，在本阶段即被否决，未进入主机分叉。

因此在当前模型下，SDK 与官方 Community-1 的 DER 差距主要是"UNKNOWN 换误认"的取舍，不是可以低风险修复的缺陷。本轮为主机诊断，基线 `origin/main` `7f41e794`，没有修改生产代码或上真机；角色分离整体仍为 BLOCKED。前序对照见[三列对照](DIARIZATION_OFFICIAL_PARITY_MATRIX_20260928.md)。

## 方法

- **原因推导。** 复用六段固定公开片的 1 秒窗口快照，按 `community_cluster.h` 相同的条件，为每个"分割激活但 frameHard=-2"的（窗口、帧、通道）给出唯一原因。六段推导出的可用集合与原生 frameHard 完全一致，之后才解释结果。
- **规模。** 每个 10 ms 缺口帧按覆盖它的未分配通道帧均分，替代旧审计中"多个窗口原因取并集"的键。
- **结果。** 每次只把一类原因的通道帧换成整窗路径的通道身份，其他帧保持不变。
  - 整窗聚类到 run 聚类的编号对应，用两边标签的共现计数确定，不使用参考标注。
  - 用 Python 移植的 Reconstruct 重建时间线，再经生产 `communityTimeline` 转换，用原评分器评分。
  - 移植版与原生 Reconstruct 的说话人标签和轮次顺序完全一致，时间差在 1 个 ulp 内（原生 arm64 构建使用 FMA）；重建的 run 路径分数与已保存分数相同。
- **判据**（评分前冻结于 `experiment.json`）：某一类同时满足"六段合计 ≥20 秒"和"新增误认 ÷ 找回时长 ≤ 现有已命名帧误认率 10.71 ÷ 830.49 ≈ 1.3%"，才能成为候选。误报单独报告。

整窗身份是不看参考标注的代理，不等于某个具体规则；它反映的是模型现有证据能给出的身份。

## 附带发现：全历史状态下短段准入不起作用

六段完整历史的 AHC 中间组为 21–46 个，远超 4，短段准入循环（`community_cluster.h:249`）一次也不执行；六段被准入的短段数都是 0。`SHORT_CAP` 的真实含义因此是"长段已形成 ≥4 个 AHC 中间组"，并不是最终人数已满，短段实际只可能在会话早期被准入。这与此前"取消 AHC 中间容量判断可恢复客户开场"的观察一致；该候选因 20 秒四人录音塌缩为三人已被否决，本轮不重开，只记录这一行为。

## 结论与建议

1. **停止以追平官方 DER 为目标调整聚类规则。** 六段上，run 策略用 195 秒 UNKNOWN 换来约 22–33 秒更少的误认和更少的换号。仓库验收标准把误认视为交付阻断，UNKNOWN 则是诚实状态，所以当前取舍方向是对的。
2. **剩余可做的方向不在聚类规则层：**
   - 提升 overlap 和短段的声学可分性，例如带 overlap 感知的 embedding 或更长的上下文。这是模型能力工作，成本需要单独评估。
   - 处理现有的 10.71 秒误认和换号。混合长 run 边界候选已定位到其中一处。
   - 用户可见层：UNKNOWN 的呈现与可读性，以及客户四位主讲人的验收。
3. **如果产品愿意用更多误认换更少 UNKNOWN，** 需要业务方明确可接受的误认率和换号上限。本轮不代做这一取舍。
