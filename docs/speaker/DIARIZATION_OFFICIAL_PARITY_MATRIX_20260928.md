# 六段公开片"官方 / 整窗 / run 路径"三列对照（2026-09-28）

**结论：在固定六段 2–4 人公开片上，SDK 与官方 Community-1 的差距全部来自生产 run 策略，而非模型移植或聚类实现。** 未修改的官方完整管线加权严格 DER 为 14.61%，同一批 1 秒张量走生产原生聚类的整窗路径为 14.56%，两者几乎重合；生产 run 路径为 27.44%。run 策略多出 195 秒漏检，同时减少 33 秒身份混淆和 20 秒误报。AISHELL-4 三人片第三人在官方管线中同样召回为 0，属于模型或数据边界，不再作为 SDK 根因追查。

本轮为主机诊断，不是 SDK 真机验收，不改变角色分离 BLOCKED 状态；也不能与官方完整 AISHELL-4 11.7%、AliMeeting 20.3% 相减。基线为 `origin/main` `7f41e794`，没有修改生产代码、模型、阈值、窗口或 hop，也没有构建或安装 HAP。

## 损失所在层

[覆盖损失分解](DIARIZATION_BOUNDARY_PUBLIC_MATRIX_20260928.md)与本表逐段吻合：各段"分割/计数不足"时长等于官方或整窗漏检，合计 80.89 秒，是官方管线共有的；"检测到但无身份"合计 195.40 秒，是 run 策略独有的。后者的局部证据桶可以重叠，不能相加：涉及短 run 未准入 100.71 秒、涉及 overlap 或被阻断 mask 100.54 秒、仅无 run 分配 23.85 秒。

各段情况不同：

- **AliMeeting 2 人**：以短 run 未准入（28.42 秒）和无 run 分配（11.09 秒）为主。整窗恢复 41.59 秒，混淆反而减少 0.15 秒，run 保护在这里只有损失、没有收益。
- **AliMeeting 4 人和 AISHELL-4 4 人**：以 overlap 或被阻断 mask 为主（51.12、25.98 秒）。整窗分别恢复 73.02、38.91 秒，但混淆增加 7.76、13.02 秒，属于真实取舍。
