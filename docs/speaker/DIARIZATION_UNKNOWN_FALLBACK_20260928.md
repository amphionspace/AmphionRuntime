# UNKNOWN 回退：用有限误认换更少 UNKNOWN（2026-09-28）

**结论：按用户决定，采用"没有 run 证据的语音回退到通道整窗声纹"。** 在 6 段公开片和 6 场从未参与设计的 AISHELL-4 会议（共 36 分钟）上，UNKNOWN 由 182.6 秒降至 2.1 秒，严格 DER 由 21.10% 降至 12.47%。合计误认 74.9 秒、同人换号 62 次，均低于官方 Community-1 的 93.5 秒、101 次，但高于当前 SDK 的 37.5 秒、36 次。有 3 段误认超过官方，逐段列于下文，**不宣称逐段达标**。

Mate80 真机上，4 个锚点和 6 段公开片的公开结果与主机生产 Session 重放逐项一致，生命周期和 native stream 全部通过。公开 6 段真机严格 DER 为 13.57%，误认 32.25 秒、换号 27 次，官方为 14.61%、44.19 秒、56 次。角色分离整体仍为 BLOCKED：内存趋势仍 INCONCLUSIVE，完整 16 段、长会议、Android 与最终发布门禁未执行。

## 用户决定与边界

2026-09-28 用户确认了以下四点，并已写入 `docs/engineering/ASR_CONTRACTS.md`（由根 AGENTS.md 按任务引用）：

1. 产品可以接受认错一些人，来换更少的 UNKNOWN，不涉及模型训练。
2. 边界是"不差于官方"，判定口径按合计。
3. 由回退找回的身份不单独标记。
4. 采用候选 1。

前序分析见[三列对照](DIARIZATION_OFFICIAL_PARITY_MATRIX_20260928.md)和[帧级归因](DIARIZATION_UNKNOWN_ATTRIBUTION_20260928.md)。帧级归因按 1.3% 的误认门槛判定时，没有任何一类 UNKNOWN 可以恢复；本轮门槛改为用户给出的"不差于官方"。

## 改动与不变量

`community_cluster.h` 的 run 模式分两步分配：

1. 原有的 run 证据分配保持不变。
2. 对没有可用 run 证据的激活通道帧（overlap 帧、未准入的短段、整通道重叠），用该通道的整窗声纹对同一组中心打分，只在该帧仍空闲的身份中分配。

保持不变：

- run 证据标签。任何帧的原有身份都不会被覆盖。
- 窗口级 `hard` 投票，即身份注册表的证据。
- 模型、窗口、hop、阈值、Fa/Fb 与人数上限。
- 已提交窗口的冻结。
- VBx 已识别、但因超出 4 人上限而未保留的声音，打分为 -inf，仍保持匿名。

**语义变化：** 从未形成身份的新声音（例如只出现在短段里、未被准入的第五个人）现在会归入最接近的已有身份。官方管线也是如此。原有 3 条"此类语音必须保持 -2"的测试断言，已改写为新的不变量："不新建身份、不成为窗口证据，但帧级有身份"。

## 附属问题：整句没有角色段（既有，未修复）

- **症状。** 部分 ASR 句子没有生成任何 `speakerTextSpans`，整句对用户显示为 UNKNOWN，即使该时间段已有具名的声学轮次。
- **证据。** 10 个输入中有 4 个出现该问题，base 与本 PR 完全相同：
  - AliMeeting 4 人：一句覆盖 1.3–170.7 秒，898 字，占全片文字的 97%；
  - AliMeeting 3 人：一句覆盖 30.4–93.9 秒，276 字；
  - AISHELL-4 3 人：一句覆盖 103.2–106.5 秒，14 字；
  - 客户录音：一句覆盖 44.5–49.4 秒，18 字。
- **影响。** 在这两段 AliMeeting 片上，即使声学轮次已无 UNKNOWN，用户看到的大部分文字仍是 UNKNOWN。它决定了这两段的可读性，本 PR 的改善在这两段几乎不可见。
- **与主问题的关系。** 这不是回退引入的，也不是聚类问题，而是出现在原句与声学轮次对齐之后的文字层，或更早的 ASR 断句层。
- **原因未证实。** 两段 AliMeeting 片中出现问题的句子都异常长，指向远场重叠场景下 ASR 没有断句；但客户录音那一句只有 4.9 秒，所以句长不是唯一条件。
- **处理状态。** 本 PR 不处理，需单独定位。
