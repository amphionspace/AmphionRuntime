# 短段身份：模型与状态归属分叉（2026-09-28）

**生产代码未变，最终交付仍阻断。** 本轮拒绝了四种不能满足防回退要求的方向：整通道一致性否决、CAMPPlus 辅助否决、放开短段 AHC 建档容量判断、短段只读查询已有身份。客户开场能恢复，不代表候选可以进入 SDK；两种状态候选分别造成四人录音人数塌缩和公开片新增身份跳变。

运行基线仍为 `196caeecb3a009c63a34763c3ef0d58b86e8bf93`，本轮分析从文档提交 `ae4e40bf` 开始，没有修改 SDK、重建 HAP/HAR 或重复真机长跑。保存状态分叉、模型对照、失败脚本及不可变源码快照见[证据索引](evidence/DIARIZATION_SHORT_IDENTITY_ABLATIONS_20260928.json)。PCM、声纹、客户原文只保留在私有缓存。

## 输入和标注归属

复用当前四实录锚点与 AISHELL-4 四人 180 秒片段，评分仍为 10 ms、零 collar、包含 overlap；身份跳变诊断另外使用既定 250 ms collar。下面的 DER 都是这一片段，不是六段加权值、官方完整 Test 集成绩或新真机精度。

四实录窗口来自已归档设备诊断；公开片 171 窗来自既有 CPU 主机推理。每个候选和自己的基线使用完全相同的保存张量，不将主机向量称为手机原始向量，也不把历史多提交输入拼成当前产物的完整验收。

客户锚点仍为 159.3 秒、WAV SHA-256 `3c263893ebed15454918ee670840f0ba47c218d5e08a4f5f5ffe6e4399ce681b`。核对本地 `dingqiao-meeting-20260918/samples.json` 后，五段录音的 WAV/PCM 哈希均与它不同；9 月 18 日的背景、播放及同人裁定不能套用到本锚点。当前四位主讲人范围继续使用[9 月 17 日人工确认记录](../../delivery/harmony-dingqiao/docs/CUSTOMER_MEETING_MOSS_AUDIT_20260917.md)。MOSS/Qwen 不作为身份真值，本轮未调用在线标注服务。

## 模型对照不能替代状态修复

先用已有短段向量和当前设备最终聚类快照检查“错误短查询是否与整通道冲突”。38 秒附近 10/10、163 秒附近 19/19 个错误查询都与整通道一致；166 秒附近也是 4/5。一致性检查无法否决主要错误。同一发言的滑窗覆盖不计作独立样本，最终中心也不等同于首次冻结时的中心。

随后只对固定失败片段、独立 reference 发言和客户锚点运行仓库已有 ERes2Net、CAMPPlus，CPU 单线程，不改模型参数，不补静音，也不搜索阈值。官方 RTTM 裁纯和登记参考仅用于外部模型能力诊断，没有输入 SDK：

- CAMPPlus 能分开 reference 裁纯的 163.829–164.217 秒女性、166.004–166.500 秒男性及其 166.1–166.4 秒子段；客户开场也匹配独立的返回发言。
- ERes2Net 对 38.630–38.780 秒裁纯片段正确，但在 163/166 秒仍误认。没有一种替代模型统一解决这些短段。
- 改用实际 clean run PCM 和现有 VBx 训练归属构造 CAMPPlus 中心后，它仍支持 38 秒的 10/10、163 秒的 19/19 个错误短查询；166 秒的 5 个错误查询则全部指回正确的男性。客户开场 6/6 个窗口匹配返回人物。

因此“增加第二模型即可阻止短段误认”的假设被否决。裁纯结果与实际 run 结果不同，也提示必须区分声学边界污染和短向量可分性，不能统称为聚类错误或据局部收益更换模型。

技术限制单独保留：ERes2Net 对 52/70 ms 输入返回的有限向量幅度很大，初版分析的 float32 norm 溢出；`results-float64.json` 从同一原始向量重算，初版没有覆盖。这不是有效置信度证据，也没有接入产品。第一次生产中心分析使用错误的 `vbxPriors` 字段名，在评分前退出；正确字段为 `priors`，V2 保留了提取快照和新结果，原失败日志仍在。

## 两个单变量状态分叉均被否决

所有分叉复用 PCM 对应的原有分割、embedding、ASR 和回调顺序，只运行保存状态及生产 Session。最终人数上限仍为四，不传 oracle 人数；没有调整 timeout、窗口或相似度阈值。

建档分叉只移除 `next <= maxSpeakers`，没有强制新建任何组。最早人数差分是四人短录音的 `cluster-1.bin`：短段训练数由 1 变为 2，AHC 中间组由 4 变为 5，VBx 都保留 3 组；原来的合法短组恢复因此从开启变为关闭，输出由四人降为三人。它证明直接取消容量判断会影响已有短人声的恢复，不是仅修好客户开场的局部改变。单人仍为一人、124 秒仍为四人，不能抵消这一金丝雀红灯。

查询分叉保留当前完整 mask 归属检查，只允许未获训练准入的同类短段查询既有中心。公开片 18 次、客户 17 次 preview/commit 的训练成员、AHC、VBx prior 和容量选择完全一致；但公开片 reference `004-M` 在 158.185 秒新增从自身编号到 `005-M` 编号的跳变，位于既定 250 ms collar 外。**只读查询不污染档案，仍会产生用户可见的身份误认。** 这与早先独立短向量查询的失败属于同类风险，不能以 UNKNOWN 减少或 DER 改善放行。

## 验证范围与下一步约束

本轮完成同输入的原生分叉、四个实录锚点的建档候选回放、两输入的查询候选回放和统一公开评分。保存状态重放检查已发布对象冻结、唯一 session final 和状态清理；它不替代真实 API 时序、手机最终展示、RTF、RSS 或断网验收。本轮没有新的设备资源结论，也未进入完整 16 段或最终组包。

下一次修复需同时回答两个独立问题：短段参与训练怎样不改变已经支持的身份分区，以及不参加训练的短查询怎样在证据不足时拒识。先沿新增 158.185 秒错误的原窗口检查分割、mask、向量及重建投票的首次偏离，不能继续仅凭总体 DER 选择候选。若需要校准拒识分数，应先冻结独立标注协议，再在未用于校准的公开片和实录锚点验收；不能根据本轮几个错误区间挑一个“刚好通过”的阈值。

当前短段身份、完整实录、长期资源趋势和同最终产物证据仍未通过。已有 arena 回收和 mask 所有权修复的有效证据继续复用；本轮所有候选均为 non-canonical，不进入发布结论或最终 PR。
