## 首个错误状态与修复边界

时间轴原始错误是 hop 改为 2 秒后，native 重建仍将第二窗 sample 32000 当成 sample 16000。此前的绝对起点修复保留。

身份退化的错误状态是公开批次定稿时删除原算法仍需使用的历史 segmentation/embedding。最初单个代表窗口、后来首次建档整批窗口都不等价于原始历史分布。60 秒候选在 585.520 秒裁剪后的尾批将返回者的 VBx prior 压到约 `5.68e-14`，只剩 3 类；586.465 秒起公开标签错误。此前同状态分叉已经证明保留全历史可消除此退化。

本轮将公开结果冻结与聚类输入存续分开：

- 原始 Float32 segmentation/embedding 无损写入本 session 的两个临时文件。提交时读取已完成窗口的准确前缀，不引入未来输入。
- 公开定稿仍冻结，10 秒预览仍可撤销，`finish` 处理剩余尾段。迟到结果仍由现有 session/job 身份检查丢弃。
- 身份登记仍按稳定 `jobId/channel` 投票，移除失败候选的建档窗口裁剪逻辑。没有强制合并、复制身份或隐藏 UNKNOWN。
- 文件归属 client；取消或结束后待 native 工作静止再删除，存储失败走明确降级路径。

磁盘保存避免 Session 长期持有全部 tensor。每次原生聚类仍需读入历史，因此**这不是无限时长的恒定内存/计算保证，也不是增量聚类算法**。不能把“落盘”直接写成“RSS 已稳定”。

## 剩余失败的最内层证据

所有候选在 464.965 秒仍有误认。完整历史下，native 在 SDK 身份映射前就输出错误类别；覆盖该时点的 5 个活跃局部通道有 4 个被 native 分到该类别。SDK 原样映射这一类别，不是文件裁剪、迟到回调或公开标签复制引入，见 `remaining-error-state.json`。这不证明整套模型无法改善，但证明本轮无损状态修复没有改变这处 native 判断。
