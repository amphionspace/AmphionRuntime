# 30 / 60 / 120 秒角色定稿周期对照

本文件保留 `052b4ea3` 的裁剪候选失败现场。后续不改模型和参数的无损证据生命周期修复，以及更新后的对照，见 [状态修复报告](DIARIZATION_EVIDENCE_LIFECYCLE_20260927.md)。下表不是最新修复后的指标。

## 结论与合入状态

**没有可选为交付默认值的已验证短周期。PR #226 保持 draft，身份精度红灯阻断合入。**
30 秒缩短等待，但保留了 120 秒已有的短插话误认；60 秒修正其中一次短插话，却在尾段把返回的老说话人误并到其他身份。
三个候选均有已知身份失败，按本轮停止条件停止参数修改，不对失败候选继续真机长跑，不运行没有合入意义的完整发布矩阵。
默认值仍为 120 秒，这只是保留原行为，**不代表 120 秒已经验收通过**。

时间轴、临时反馈与身份准确性分别报告。用户原始 47.82 秒单人录音的时间轴修复和录制中反馈已有真机证据；本轮多人回放证明身份定稿仍不能结案。

## 原因、参数与触发条件

120 秒来自 PR #192 的不可变批次设计（`d11ad0a6`），是控制修订等待和待处理数据量的工程默认值。
原设计文档已经声明并非精度最优值，没有找到 30 / 60 / 120 秒的既有比较实验。

当前 Harmony Community 路径的实际参数：

| 参数 | 实际值与作用位置 |
| --- | --- |
| 模型逻辑窗口 | `SpeakerDiarizationLocalClient` 创建 scheduler，10000 ms |
| native 输入 | 同一 client 固定 160000 samples；尾窗只右补零 |
| 推理 hop | client 默认 2000 ms；scheduler 类型本身的旧默认值不代表调用点实际值 |
| 临时角色更新 | Session 中处理进度与模型进度的最小值，每跨 10000 ms 尝试一次 |
| 定稿目标周期 | `DiarizationCommitClock`，本轮内部回放传入 30000 / 60000 / 120000 ms |
| 证据右侧余量 | 保持原有 `ceil((max(deadline, boundary)+1500)/2500)*2500`；这里的 2500 是证据截止取整，不能称为当前推理 hop |
| 单窗 / finish timeout | 10000 / 15000 ms，均未修改 |

首次临时更新要求已有未定稿 ASR 原句、ASR 处理时钟与模型完成时钟都跨过 10 秒刻度，且没有结束或降级。
预览只修改冻结身份注册表的副本，不登记最终身份。没有原句或处理尚未完成时不会凭时钟造结果。

定稿时钟达到 `plannedThrough + period` 后，选择不超过目标的最后一个已有 ASR endpoint；没有这样的 endpoint 时才取目标之后的第一个。
还需等待模型证据覆盖固定截止点。因此目标周期不是用户每句话的固定等待上限。
`finish` 要求 ASR 尾结果已观察到、模型工作已排空，然后处理实际录音末尾；不会等待凑满周期。

缩短周期改变了不可回滚身份的登记时刻、首次建档证据集合、历史裁剪位置、预览/定稿次数和每次聚类的数据分布。
VBx 在每次聚类中重新估计先验；保留一些代表窗口或最初建档窗口，不等价于保留全部历史推理状态。
不能据此预设更频繁更慢，或更短周期一定更省内存。

## 输入与回放有效性

- 真机只采集一次固定 120 秒基线，保留逐次输入、ASR 处理完成、ASR 原句/endpoint、模型窗口完成、finish、drain 和公开回调的有序日志。
- 回放直接执行当前生产 `Session / CommitClock / CommunitySpeakerIdentity / TranscriptState` 和 C++ 聚类/重建函数。每个候选从 session 初始状态按同一真实事件顺序运行，保留身份历史、冻结、裁剪、预览和尾段处理；不是几次独立离线聚类。

- 以下三个候选的等待采用相同的立即返回调度：事件到达时间来自手机，但排除候选聚类执行延迟。它们是周期筛选数据，**不是 30 / 60 秒手机延迟或性能实测**。

## 最早错误状态与单变量分叉

原用户时间轴故障的首个错误状态是第二个模型窗口：真实起点 sample 32000 被重建为 sample 16000。
绝对起点修复后，原单人录音角色覆盖末尾从 26.845 秒恢复至 44.834 秒，文字不变；该症状与本轮身份问题分开归因。

本轮已有短插话错误：108.38–109.43 秒的 MTD011UID 在若干窗口与其他人物共用局部通道，另外一些独立通道又因 clean frames 不足未用于建档。
在 30 / 120 秒提交时，尚无其后续长发言证据，现有 native 分配将其指向已有身份。60 秒对应批次纳入后续长发言，修正了这一处，但不能据此宣告胜出。
这一错误在冻结和裁剪之前已存在，见 `short-interjection-segmentation.json`。

60 秒新增退化的最早错误状态发生在 585.520 秒边界裁剪后的尾段聚类。历史注册表仍有 4 个冻结身份，native VBx 却将返回者的 AHC 类先验压至约 `5.68e-14`，低于现有 `1e-7` 存活条件，最终只产生 3 个中心。
随后一个 native 类同时承载老身份 2 和身份 3 的历史票数（1529 与 14021），一一映射选择身份 3，老身份 2 从当前映射消失。586.465 秒起公开时间轴出现返回者的错误编号。

## 120 秒真机性能与生命周期

600 秒输入的 296 个模型窗口起点完整保持 0、2、…、590 秒，未跳窗。
模型推理均值 / P95 / 最大为 575.75 / 668.98 / 723.61 ms；`inference_time / hop` 均值 0.288。
更直接的积压观测：模型完成处音频延迟均值 640 ms、P95 840 ms、最大 1860 ms；各分钟均值为 617–674 ms，没有持续增长趋势；待提交 descriptor 最大为 0。
ASR 队列最大 90 个 20 ms 帧（1.8 秒）。这些队列/时钟观测一起支持“此输入此次 10 分钟未见持续音频积压”，不能只用模型倍率判定整个 SDK 实时。

手机预览聚类 56 次，总计 4143 ms，均值 73.98 ms、最大 701 ms；定稿 6 次，总计 276 ms，均值 46 ms、最大 65 ms。
实测首个临时角色 13.180 秒、首批冻结 124.593 秒；finish 到 complete 为 954 ms。
55 个非空 final，空 final 为 0，finish 前 last 为 0，之后恰好一次 last 和 complete，顺序正确，error 为 0，native stream 归零。

RSS 头尾中位数 649.906 → 690.613 MB，增长 40.707 MB，斜率约 +4.426 MB/min，线程数 71 → 71。
runner 的 64 MB 阈值判为 PASS，但本报告将“RSS 是否稳定”标为 **INCONCLUSIVE**：本诊断采集保留六万多条逐帧事件及索引，也有诊断预览数组保留，尚未隔离其内存贡献。
不得据此称 RSS 已稳定，也不能仅凭本次诊断 RSS 增长判定正常 Release 路径泄漏。
30 / 60 秒因身份筛选失败，未进行候选手机性能对照，故没有它们的手机 RSS、队列或 finish 性能结论。
