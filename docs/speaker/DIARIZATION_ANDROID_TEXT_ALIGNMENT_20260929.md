# Android 中英空格对齐修复的真机验收（2026-09-29）

**结论：PR #244 的 Android 调用方验收通过。** 在 TECNO KI8 上用同一批 PCM 对 base 与本 PR 做 A/B：9 条目标句中有 7 条从整句 UNKNOWN 变为具名说话人，声学轮次和识别文字逐项相同。剩余 2 条的原因已逐条查明，都不是对齐失败。

本 PR 只同步 Harmony 已有的中英空格规则，不包含 Android 的警务改写位置追踪或 JNI run 级声学证据，**不能据此宣称 Android 与 Harmony 已全面一致**。角色分离整体仍为 BLOCKED。

本 PR 提交 `c27faac5`，base 为 `acf477c2`（`origin/main`），两份快照只有本 PR 的 2 个文件不同；未入库的模型、native 库和授权等构建输入逐字节相同。

## 问题与改动

[文字归属报告](DIARIZATION_SPEAKER_SPAN_PROVENANCE_20260928.md)在 Harmony 上定位到：sherpa CT 标点模型只在两个 ASCII 字符之间保留空格，因此中英之间的空格一定被删掉，导致展示文本无法与 ASR token 对齐，整句退回 UNKNOWN。Android 当时未同步该规则。

本 PR 让 Android 的 `tokenTextBoundaries` 接受与 Harmony 相同的三种情况：非双 ASCII 相邻字符之间的空格被删除、标点替代分隔符、句首空格。两个英文词被粘连，以及没有位置记录的词语改写，仍然拒绝猜测身份。

## 设备与性能口径

TECNO KI8 算力较低。按用户明确口径，**性能以 Mate80 为准验收**，本机只用于验证文字归属这一行为。实测该机：

- 159 秒客户录音与 124 秒四人录音：base 与本 PR **都**以 `FINISH_TIMEOUT` 降级收尾，角色窗口没有任何声学轮次，两端识别文字与生命周期断言完全相同。这是本机吞吐问题，与本 PR 无关，也无法用于判断文字归属。
- 20 秒以内的输入可以正常完成定稿，因此行为证据取自这类输入。

## 真机 A/B

三段目标输入由验收集的英文接中文 TTS 条目拼成（16 kHz、单声道、PCM16、1.2 秒间隔），最后一条取客户录音中经 ITN 改写的数字句。base 与本 PR 各跑一次，输入哈希相同。

| 输入 | 时长 | 定稿 | 声学轮次 | 识别文字 |
| --- | ---: | --- | --- | --- |
| targeted-1 | 12.9 s | 未降级 | base 与 PR 逐项相同 | 逐条相同 |
| targeted-2 | 14.7 s | 未降级 | base 与 PR 逐项相同 | 逐条相同 |
| targeted-3 | 19.3 s | 未降级 | base 与 PR 逐项相同 | 逐条相同 |

逐句身份（`speakerIndex`，-1 表示 UNKNOWN）：

| 句子 | base | 本 PR |

| 这个文件用WPS打开。 | -1 | **0**（含推断补全） |
| 我用WPS写好了。 | -1 | **0**（含推断补全） |

剩余 2 条 UNKNOWN 的原因：

- **提取了DNA样本。** 覆盖该句的声学轮次本身就是 UNKNOWN（`speakerIndex=-1`），没有可继承的身份。这与对齐无关，base 和本 PR 必然相同。
- **下面开始会议1234 56789。** 该句带 `overlap=true` 和副说话人 `[0]`，按既有重叠规则，整句摘要保持 UNKNOWN。此外该句经 ITN 把中文数字改写为阿拉伯数字，而 Android 的 `AsrResult` 没有 ITN 位置映射，本 PR 也不新增——这属于后续项 A1（Android 改写位置追踪）。
