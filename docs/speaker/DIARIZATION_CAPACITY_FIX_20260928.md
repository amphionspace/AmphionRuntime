## 修改边界

要改变的是“超过人物容量时把已分开的身份重新合并”。生产 native 推理现在为每个 clean run 保存自身 PCM 的 RMS，经独立快照存储传到聚类；只读取当前可用窗口前缀，后续窗口不能修改旧证据。

只有 VBx 存活身份超过配置容量时，才按 posterior 与 run 长度加权计算各身份的 RMS。保留不低于最响身份一半的既有身份；如果仍超出容量，按音量保留容量内的身份。这个规则选择已有身份，不强制建立指定数量的组，也不把其他身份并入它们。声学最优匹配属于被排除身份时保留 UNKNOWN，不转贴给次优前景身份。原始分割及 overlap 保留。

容量内不进行音量筛选，因此轻声人物不会仅因相对音量低而被删除。代价是超容量时优先较响声音，不能将它称为通用背景分类器或所有音量均通过。此取舍沿用客户明确的四位主讲人范围；完整公开回归仍是后续放行条件。

保持不变：模型、特征、分割、embedding、训练准入、窗口/hop、ASR、原文、冻结提交及生命周期。短段向量查询没有混入本次补丁；未增加 timeout、网络请求或跨会话缓存。Android 的整窗旧接口尚未传 run 音量，仍走旧路径；本轮不宣称 Android 身份行为同步改善。
