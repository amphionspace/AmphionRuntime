# 角色分离本轮优化总结（2026-10-01 至 10-03）

**结论**：本轮合入 6 个 PR（#246–#251），解决了三类用户可见的问题：

- Android 与 Harmony 的聚类路径不一致，四人会话少认一个人；
- 干净的单人句被标成"推断"；
- 长会议在收尾超时、或远场音量悬殊时丢失或塌缩角色。

两端都完成了真机验收。AISHELL-4 三人、四人 **30 秒短会话把人认少**的问题仍未解决，是角色分离身份精度的**交付阻断项**。原因和出路见[讲解页面](DIARIZATION_SHORT_SESSION_COLLAPSE_20261003.html)。

## 起点

2026-10-01 在 TECNO KI8 / Android 13 上对比 main（`acf477c2`）与已交付的 Android 0.3.9（`74e94a27`），并用交付包内的 AAR 复核：两版在 11 组输入上输出逐项相同。接口与生命周期通过，但身份精度和用户可见体验不通过：

- 19.58 秒四人实录只分出 3 人；
- 干净的单人句都带"推断"标记；
- 收尾超时后角色全部丢失；
- Android 没有使用 run 证据，且定稿后会裁剪历史，与 Harmony 不一致。

## 真机验收

验收对象是整合状态 `44d6a2a1`（#246–#249 合并后的代码）和 #250 的 `f463e354`。合入时各 PR 合并 main 后的内容，与验收版本逐字节一致。

**Android（TECNO KI8 / Android 13，release AAR，0.3.9 交付 Demo 载体）**

- 角色分离 11 个输入与移植版逐项一致，生命周期全部唯一 last → 唯一 complete；两段 180 秒会议收尾超时抢救后保留前段。
- #250 后，AliMeeting 180 秒抢救后的前段从 1/4 人变为 4/4 人（90.03% → 19.04%）。
- `DingqiaoFinishFlushRegressionTest` 3/3 通过；`DqSdkCornerCaseTest` 26/27 通过，`a11a` 缺少经核对的单人连续语音，**未覆盖**。
- `DqRuntimeFastLoadInstrumentedTest`：冷启动准备约 2.3 秒，超过 2 秒门槛。与改动前 main 交替对照无差别，属 KI8 低端机的既有限制。

**Harmony（华为 nova 14 Pro / OpenHarmony 6.0.2.130 / API 22）**

Mate80 离线，经用户同意以 nova 代替。

- `diarization-windows` 两段 180 秒会议 PASS：AISHELL-4 两人识别 2 人，AliMeeting 四人识别 4 人；stop → complete 0.8–1.2 秒；推理耗时为音频时长的 0.56 倍。
- 开启角色分离的 `cancel`、`reentrant`、`start-write-reload`、`user-sequence`、`finish-shutdown` 全部 PASS（`finish-shutdown` 使用规定的 AISHELL-3 语料）。
- 测试授权为内部签发的不绑定设备授权，30 天有效，只用于隔离的测试构建，未提交。
- nova 推理够快，不会触发收尾超时，所以抢救路径在 Harmony 上只有单测覆盖。

证据保存在本机目录 `~/.cache/amphion-runtime/diagnostics/main-device-diarization-20261001/`（`runs/`、`harmony-runs*/`、`analysis/`）。原始 PCM、声纹和完整文本不提交。
