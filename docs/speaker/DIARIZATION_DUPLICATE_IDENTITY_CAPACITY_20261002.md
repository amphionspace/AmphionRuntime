# 超出人数上限时先合并重复身份（2026-10-02）

**结论：** run 证据路径中，VBx 偶尔会把同一位说话人拆成两个身份。身份数超过 4 人上限时，按音量的容量选择会让这个重复身份占住名额，把一位较轻但真实的主讲人整段丢弃。

修复后，只在超出上限时，先合并"自有训练向量"高度相似的身份，再按原规则做容量选择。容量选择规则不变：只有身份数仍超出上限时，才按音量把轻声或背景身份匿名；合并后若不再超限，结果与从未分裂的会话相同，不施加音量门槛，轻声身份会保留编号，但不会挤掉响亮说话人的名额。仅仅因为名额已满，不会合并不同的人。

## 现象与最早偏离

102.38 秒四人实录 `0b31db1204ab`（参考为 MOSS 辅助标注）在 run 路径下的结果：

| 阶段 | 发生了什么 |
|---|---|
| VBx | S04 被拆成两个身份，先验分别为 0.085 和 0.141，共 5 个身份 |
| 容量选择 | S02（参考时长 18.6 s，RMS 0.027，不到最大值的一半）被整段丢弃，S04 的重复身份却保留 |
| 结果 | 严格 DER 43.23%；S02 召回 8%，S04 召回 42% |

整窗路径下 VBx 只给出 4 个身份，不触发容量选择，DER 为 5.37%。

## 改动

- 只改 `community_cluster.h`；只在 run 证据带 RMS、未走 AHC fallback、且 VBx 身份数超过上限时生效。
- 每个训练向量只归入其后验最大的身份，以此计算各身份的"自有向量"均值。若两个身份的自有均值余弦 ≥ 0.6，合并相似度最高的一对，然后重建质心。重复上述过程，直到不超上限或没有满足条件的组对，然后进入原有的容量选择。
- 使用自有向量而非后验加权质心：VBx 后验较软时，加权质心会互相混合，导致不同的人看起来很相似。这种情况由原有容量单测锁定。

## 证据

用主机端的共享 `Process()` 重新提取窗口，与 TECNO KI8 真机采集逐项一致：分割 0 差异，整窗及 130 个 run 向量的余弦均为 1.000000，run 范围和 RMS 完全相同。

| 检查 | 结果 |
|---|---|
| 相似度区分 | 12 段输入中，唯一的同人拆分组对为 0.774；不同人组对最高 0.389；客户会议各身份之间最高 0.274 |
| 全历史聚类，12 段 | 只有 `0b31` 改变：43.23% → 6.58%（误认 6.92 → 1.41 s）。6 段公开会议、AMI 600 s 及其余实录逐段不变；7 段官方标注加权 DER 维持 11.64% |
| 客户会议原音 | 有 6 个身份、超出上限，但输出逐段不变，没有发生合并 |
| 真机窗口，11 段 | 逐段不变 |
| 流式回放，5 段 | 用 Harmony 真实 ASR 时间线和当前会话代码回放，只有 `0b31` 改变，数值同上 |

## 范围与限制

- 同人拆分的正样本只有这一例，0.6 的阈值依据有限。
- `0b31` 的参考是 MOSS 辅助标注，不是人工真值。
- 未超上限时的重复身份（同一人显示为两个编号）不在本次处理范围内。
- Android 在 run 证据移植（#248）合入后才生效；#248 已在 TECNO KI8 上用包含本修复的 release AAR 完成 11 个输入的真机验证。
- 没有 Mate80 设备，本次没有 Harmony 真机验收。这是 SDK 运行行为修改，合入前必须在同一提交、同一产物上补做 Harmony USB 真机验收；在此之前本修复不能合入。
- embedding 等声纹数据只保存在本机私有目录，不提交。
