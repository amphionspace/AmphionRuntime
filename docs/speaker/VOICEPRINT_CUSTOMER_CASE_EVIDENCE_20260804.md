# 2026-07-29 Harmony 机主识别客户样例证据

## 证据范围

本说明只沉淀客户提供的 3 段注册语音、C1～C3 三段回放 WAV 与回调日志得到的工程判断。
原始 WAV 和日志不提交仓库；源压缩包 SHA-256 为
`b7fc381c443eeec9b2b9385114c3713f431c1eb9c0c80a1d9fa057707cde5267`。

这些样例能复现产品症状并区分失败层，但样本量不足以估计 FAR、FRR、CER/WER 或选择商用阈值。
离线窗口分数使用与 Harmony/Android delivery asset 字节一致的 ERes2Net 模型复算；它用于解释趋势，
不替代同版本 SDK 的 Harmony 真机回放。

## 固定输入与调用参数

- SDK：Harmony `0.2.8`。
- `enableVoiceprintVerification=true`、`enableSpeakerVad=true`，有效 `voiceprintIds` 为 1 个。
- `speakerVadThreshold=0.35`；未显式传窗口参数，因此 0.2.8 使用 `1.0 s` 窗、`0.3 s` 步长、
  连续 2 个低分窗触发 endpoint。
- `vadBegin=60000`、`vadEnd=60000`、`maxAudioDuration=62000`；三段测试音频均未触发这些时长上限。
- C1/C2/C3 分别为 `10.34 s`、`14.50 s`、`11.88 s` 的 16 kHz、16 bit、单声道 PCM。

三段注册语音分别为 `7.12 s`、`6.92 s`、`6.92 s`，无削波。按 SDK 的“逐段 embedding 求均值并
归一化”方式注册后，单段 embedding 对合并模板的余弦分别为 `0.918594`、`0.945935`、
`0.926679`。因此当前证据不支持把 C1～C3 首先归因为注册失败或注册音频格式错误。

## 用户可见症状

| Case | 声学关系 | 公开 final 与分数 | UI 结果 | 精确失败断言 |
| --- | --- | --- | --- | --- |
| C1 | 机主与他人轮流接话 | 含机主内容和“你好”的混合 final，`0.467833` | pass | 非目标尾音进入已接受文本 |
| C2 | 机主说话时他人插话 | 含“准备去上海”和“你好”的混合 final，`0.308728` | drop | 机主内容随混合句一起丢弃 |
| C3 | 他人近麦、机主远场 | 机主相关 final `0.296824`，他人 final `0.325701` | 均 drop | 近场干扰下机主内容不可恢复 |

随后一次 `onComplete`。本组症状不是提前结束或生命周期归属错误。

## 0.2.9 Harmony 真机时间线（2026-08-04）

在 HDC 真机 `7GK…5655` 上，以 `origin/main@1ca9108`、唯一 `ZH_EN` HAP、同三段 enrollment、
同 C1～C3 PCM、实时 `20 ms` 喂入和阈值 `0.35` 回放。诊断载体只增加逐窗/endpoint/final 时间线，
没有改变模型或门禁决定。`1500 ms` 窗、`500 ms` 步长、连续 2 个低分窗的基线完整重复两次，
文本和分数一致：C1 泄漏、C2 目标短语随混合段丢弃、C3 目标短语丢弃。

逐窗时间线把失败定位到 Speaker VAD 判决粒度：

| Case | 关键窗口轨迹 | Speaker endpoint | 业务结果 |
| --- | --- | ---: | --- |
| C1 第二段 | `0.571 → 0.596 → 0.459 → 0.072 → -0.036` | `7.50 s` | endpoint 前“你好”已进入同一 final，混合段 `0.467833` 被接受 |
| C2 重叠段 | `0.490 → 0.486 → 0.317 → 0.003` | `11.50 s` | “准备去上海，你好”整段 `0.308728` 被丢弃 |
| C3 目标段 | `0.382 → 0.371 → 0.412 → 0.448 → 0.508 → 0.246 → -0.020` | `6.50 s` | 可见连续目标窗，但公开 final 被尾部污染拉到 `0.296824` 并丢弃 |

所有有效切段均由 Speaker VAD 主动触发；没有 ASR/native endpoint 抢先造成这三条失败。纯非目标窗为
负分或接近 0，当前证据也不支持“embedding 完全无法区分两人”。

另做一次固定阈值的时序探针：只把窗口/步长缩到 `1000/300 ms`，连续低分仍为 2。结果：

- C1 真正通过：`准备明天去上海` 单独以 `0.510320` 放行，“你好”未进入放行文本。
- C2 仍失败：含“上海”的重叠段 `0.290611` 被丢弃。
- C3 仍失败：`去上海` 段 `0.287265` 被丢弃，只保留了不含目标关键词的后半段。

因此短窗只能解决 C1 的顺序换人尾音，不能满足 C2/C3“重叠时仍保留目标短语”的产品契约。主机
验收已收紧为：每条 C1～C3 放行文本都必须包含目标关键词“上海”，且任何放行文本不得包含“你好”。
在该精确门下，短窗探针为 `C1 PASS / C2 FAIL / C3 FAIL`，不得再以“至少一条机主 final 通过”报告
整体成功。对应本机 artifact run ID：

- `20260804-142901-voiceprint-customer-cases-e005914a`（1500/500 逐窗基线）；
- `20260804-143605-voiceprint-customer-cases-short-window-b6f7e4ce`（1000/300 精确业务红灯）。

## 相同模型的离线诊断

按 0.2.8 的 `1.0 s / 0.3 s` 滑窗对完整 WAV 复算：

| Case | 整段余弦 | 窗口 min / p50 / max | `score >= 0.35` 窗口 |
| --- | ---: | ---: | ---: |
| C1 | 0.555873 | -0.071 / 0.178 / 0.602 | 13 / 32 |
| C2 | 0.580287 | -0.130 / 0.398 / 0.629 | 25 / 46 |
| C3 | 0.172637 | -0.144 / 0.082 / 0.647 | 7 / 37 |

离线轨迹显示 C1 在机主窗口之后进入连续低分区，但 Speaker VAD 必须等待完整窗口和连续低分确认；
这与已有 500 组 target→other 评测中 `0.88 s` 的 target 后 endpoint 中位延迟、`0.917 s` 的平均
非目标泄漏一致。C2/C3 则同时出现高低分窗口，说明“混音里存在机主证据”不等于能判断每个字属于谁。

## 已证明的架构结论

1. 当前 final 只有一个句级 `speakerSimilarity`，业务只能整句保留或整句丢弃。
2. Speaker VAD 是目标出现/离场检测器，不是语音分离器；决定产生前 PCM 已经送入 ASR。
3. 单阈值无解：要拒绝 C1 的混合 final，阈值需高于 `0.467833`；但同一 C1 中另一个应保留 final
   只有 `0.445439`。降低阈值保住 C2/C3 的机主内容又会增加非目标误接收。
4. C1 属于轮流讲话的 endpoint/尾音控制问题，可以在当前框架内继续优化；C2/C3 属于单通道重叠
   目标说话人 ASR，必须评估目标语音提取、分离或端到端 TS-ASR，不能继续以 verification 调参代替。
5. 当前 0.2.9 分支仍保留“整段打分 + 滑窗 Speaker VAD”的核心状态机；默认窗口变化不是 C2/C3
   的结构性修复，升级版本必须重新跑同 PCM、同参数、同喂入时序的差分测试后才能下结论。

## 重叠前端离线证据（2026-08-04）

在相同客户 WAV、相同三段 enrollment、相同 ERes2Net 和当前 `ZH_EN` ASR 下补做两条独立前端实验：

- WeSep BSRNN+ECAPA 16 kHz TSE：C1/C2/C3 提取后文本逐条包含“上海”且不包含“你好”；C2 用三段
  enrollment 分别条件化，三次结果一致。分离 RTF 约 `0.31`，但峰值 RSS 约 `1.94 GB`。
- SpeechBrain RE-SepFormer 8 kHz 两路分离 + ERes2Net 选流：C1/C2/C3 同样逐条通过；固定 4 秒模型
  可导出 83.6 MB ONNX，PyTorch/ONNX 输出 cosine `1.0`，主机中位 RTF `0.0276`、RSS 约 430 MB。
- Asteroid Conv-TasNet 16 kHz 两路分离 + ERes2Net 逐块选流：固定 2 秒 ONNX 为 20.15 MB，C1/C2/C3
  逐条通过；桌面 ORT 1.16.3 中位 RTF `0.0583`、独立进程 RSS 约 267 MB。C3 有一字退化，且尚未做
  ARM 真机、target-absent 与闭源许可门，因此只能作为短期 pilot 候选。

这组结果证明 C2/C3 的目标内容可以在前端恢复，也进一步证明 Speaker VAD/verification 不是正确修复层。
WeSep 和 RE-SepFormer 都不满足当前 Harmony 生产预算；Conv-TasNet 已满足主机内容与图兼容门，资源
高概率可满足当前 Mate 80，但还没有真机数据。完整逐例文本、声纹分数、模型与输出哈希见
[重叠前端实验报告](VOICEPRINT_OVERLAP_FRONTEND_EXPERIMENT_20260804.md)。

## 仍缺的证据

- 0.2.8 与 0.2.9 在同一 Harmony 设备、同一诊断载体上的严格版本差分；0.2.9 的逐窗 score、
  `svTargetConfirmed`、低分计数、endpoint 来源和公开 final 时间线已经捕获。
- C2/C3 各说话人的独立源音频和时间对齐参考文本；现有混合 WAV 无法计算分离质量或 overlap-only CER。
- 与真实部署设备、距离、方向和交通背景匹配的 speaker/session-disjoint pilot；C1～C3 只能作为固定
  回归样例，不能作为统计验收集。
