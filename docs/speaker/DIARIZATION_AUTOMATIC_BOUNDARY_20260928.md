# 自动边界候选：源侧身份约束与独立验证（2026-09-28）

**得到一个可继续验证的自动候选，尚未进入生产 SDK，整体交付仍 BLOCKED。** 它不读取参考标注、文本、预期人数或手选时间点，自动重现了[上一轮混合 run 分叉](DIARIZATION_MIXED_RUN_BOUNDARY_20260928.md)的身份修正；四个实录锚点的公开结果和临时更新完全不变。首版自动规则在独立会议中出现回退并被否决，增加源侧身份约束后挡住了该反例。新提取的三场会议未观察到诊断回退，但均超过四人能力，只能作为容量压力证据，不能代替固定六段公开集或端到端验收。

分析提交为 `7f269563`，运行代码仍为 `7f8a7e4d`。本轮仅有私有主机原型、状态重放、推理和报告变更；没有构建、安装或修改 HAP/HAR，没有调整模型、窗口、hop、timeout、聚类阈值或公开 SDK 人数上限。

## 自动规则及其边界

原型按每次聚类实际可见的窗口前缀处理：

1. 从相邻单人帧的 local channel 直接变化生成候选边界，按绝对 sample、源窗口和 frame 排序。
2. 用原始前缀的生产聚类结果作为身份空间。容量溢出时仍与全部原始中心比较；最佳中心被排除的向量保持 UNKNOWN，不改配次优人物。
3. 寻找跨界的 clean run 分区；只有两侧都达到原有长段资格 `>=0.2*589` 帧的分区，才产生独立 pooling 查询。没有新增时长或 cosine 阈值。
4. 所有合格视角必须给出一致、不同且保留的左右身份，且不能与源窗口已有的身份相矛盾。重叠窗口的一致性不被宣称为多份独立真值。
5. **最终候选还要求源边界至少一侧已有命名身份。** 完全匿名的局部通道转换不能授权改写其他窗口的 run 分区。
6. 接受边界后拆分跨界 clean run，重算长子段及其真实 PCM RMS，短子段仍为零向量，overlap 保持原样。原分割和整窗 embedding 不变，再调用原生产聚类、Session 身份分配与冻结逻辑。

后续切点必须在剩余分区中重新获得两侧长证据，不能把同一个物理边界附近的通道抖动全部切开。原型没有强制新建角色、启用所有短查询、删除 UNKNOWN 或使用文字猜测身份。此规则仍需更多反例验证；“至少一侧已命名”不是已证明充分的普遍换人判据。

## 首版失败揭示了时间归属问题

首版仅有长子段一致性，未要求源侧身份。它在20秒四人、单人/UNKNOWN、124秒四人和客户四主讲人锚点上保持所有公开结果及 updates 完全相同，并自动选中了公开片155.22034375秒的边界。

随后，独立校准 L 会议暴露反例：在33.45284375秒，源窗口先有25帧匿名 channel 2，再切到只有2帧的匿名 channel 1，之后多次切回。RTTM 显示这些短片仍属于同一 `001-M`；`002-M` 较晚才加入，且先有重叠。两个跨界长 run 的后半段确实更接近 `002-M`，但这只能证明较大区间中换过人，不能证明最早的2帧切点就是换人时间。

## 呈现结论修正与工程风险

后续检查了实际 ArkUI 渲染分支：有 `speakerParts` 时，界面隐藏 `segmentSpeakerLabel` 摘要，直接显示逐片文字角色。上一轮方法重放导出的摘要和文字标签差异，不能表述为用户同时看到冲突标题。原报告已修正，原始方法输出和 `caller-render-audit.json` 均保留。

确认存在的结构变化仍是公开片从41段变为42段，同一原句多出一个与后续文字同编号的单字段落。不能只按段落数判断体验，也不能抹去真实单字回答或换人；需要在实际调用方中验证同人连续发言的呈现。声学诊断通过不等于该体验用例已通过。

该 Python 原型会保存 encoder 张量并再次聚类，**不能直接照搬成 SDK 实现**。进入实现前必须验证固定六段2–4人公开子集，并设计按 session/generation、绝对 window/frame 归属的有界 mask 查询；不能把整场 encoder 张量长期留在内存，或每次预览重复编码全部历史。新增原生异步操作必须受现有取消、关闭和 quiescence 边界约束，不能根据当前全局 session 猜测迟到结果归属。

本轮未证明长会议 RTF/RSS、合法调度等价性、`finish/last/complete/cancel` 真机契约或新候选断网运行。既有生产 `7f8a7e4d` 的性能证据继续保留，但不能冒充这个新增推理路径的验收。尚未实施增量 encoder 迁移。
