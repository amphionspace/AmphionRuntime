## 最早偏离与单变量差分

生产 Session、身份冻结、文本对齐的主机重放与手机两个公开窗口逐字段一致，仅排除主机不具可比性的 `inferenceMs/rtf`。其后实验均固定 ASR、分割、原有长段向量及回调顺序。

### 短段丢失在 embedding 准入处发生

当前独立 clean run 不足约2秒时导出零向量。客户开场主讲人的六个重复窗口覆盖均为零向量，训练覆盖为0；较响的短语音并没有获得独立身份查询机会。六个窗口不是六次独立发言。

现有短段备用准入还要求 AHC 组数加一后不超过公开人数上限。客户首次定稿有24个 AHC 组，最终有28个，因此该条件始终阻止短段加入。AHC 中间组数不是最终人物数，不能把它当作人物容量证据。

只补算缺失短向量的实验使用相同 PCM、生产 Fbank 和锁定的 encoder/pool，不覆盖原有长段向量，不把短向量自动加入训练，也不把 reference 人数或标签送入推理。客户151窗口补算约49.7秒；这是主机诊断耗时，不是端侧性能结果。

单人录音中，92个短段均得到有限向量，但只有1个落在原 AHC 距离0.6以内。因此“短段可以直接使用长段 AHC 准入距离”的假设不成立。无约束最近中心会恢复文字角色覆盖，同时增加公开集误认。

### 客户主讲人误合并在人数压缩处发生

首次定稿的117个训练 run 经24个 AHC 组得到6个存活 VBx 身份，随后 KMeans 压为4个。最终129个训练 run / 28个 AHC 组也得到6个存活身份并触发压缩。

固定首次定稿张量，压缩前主讲人3、主讲人4、回来的主讲人1分别对应三个不同身份；压缩后三者属于同一组。这是当前输入上直接的状态差分证据，不能再把该误合并归因于 SDK 文字展示或 embedding 完全不可分。

历史提交 `6932d636` 接入 Community 时删除了此前主讲人相对音量准入逻辑。当前主讲片段 run RMS 中位数约0.076–0.098，两个背景区间约0.018/0.026。按训练 run 的 VBx posterior 和实际样本长度加权，6个身份的相对 RMS 约为 `0.997/0.455/1.000/0.842/0.869/0.224`；此前用户允许的0.5相对音量带在本例保留4个前景身份。

主机容量候选只在 VBx 超出容量时使用该规则：保留已有前景身份，不重新 KMeans 合并；所有身份先参与声学分配，未保留者映射为 UNKNOWN，避免将背景重新硬匹配给前景。没有要求凑够4组；筛选后仍超过容量会终止实验，尚未定义通用超容量产品策略。RMS 由分割 frame 中心边界估算，未声称与旧模型取样完全等价。该候选尚无端侧实现及实时证据。

## 公开集短段候选：DER 改善仍不足以放行

同一 AISHELL-4 四人180秒切片、1秒 hop、生产 SDK 提交冻结路径、10毫秒 strict 评分。下表全部是保存张量上的主机实验，不是完整官方 Test 集，也不是本次新 HAP 结果。

| 路径 | strict DER | 身份混淆秒数 | UNKNOWN秒数 | 同参考人换号数 |
| --- | ---: | ---: | ---: | ---: |
| 当前 run 路径 | 33.6679% | 2.07 | 27.20 | 2 |
| 任意短段最近中心 | 26.7701% | 3.41 | 14.19 | 7 |
| 短段加 PLDA 预测支持 | 28.0745% | 2.82 | 16.87 | 4 |
| 再要求 cosine / PLDA 最优身份一致 | 28.0262% | 2.82 | 16.96 | 4 |

预测支持仅为研发候选：比较现有身份和新身份的 PLDA 预测似然，未做可用于产品的概率校准。短段训练、原有长段匹配和模型参数没有变化。单人11句均恢复同一 ID，20秒四人仍为4人，124秒录音文字守恒，但辅助 MOSS 指出的68秒附近短换人仍需裁定；不能据 UNKNOWN 减少判精度通过。

新增具名错误区间合计1.63秒，均位于某个 reference 边界250毫秒内。250毫秒 collar、排除 overlap 的 DER 由13.1893%变为约8.1758%，**该宽松数字不能覆盖 strict 混淆增加**。换号数增加部分来自原错误区间中恢复了正确身份，也不能只按计数宣布漂移。首个公开 ID 改变则来自开头真实002-F由 UNKNOWN恢复，并非冻结后随意换号。

对166秒附近三个窗口做“原始/参考纯段 mask × 原始/清零外部 Fbank context”的2×2状态分叉，12个结果均仍最接近同一错误身份。清零上下文即可修复的假设被证伪；没有据此修改 encoder。参考 mask 仅进入离线诊断。

一次初版 PLDA 诊断使用了错误的 transform 方向，已标记 non-canonical。修正后与生产 native feature 的最大绝对差约 `6.15e-14`；报告只采用修正版本。实验失败和错误诊断均保留，不覆盖现场。

## 调用方、平台和下一步边界

三个客户路径均重放真实 Demo 的最终结果处理、段落和标签函数：文字哈希完全一致，已提交对象保持冻结，UNKNOWN、overlap、`speakerInferred/confidence=0` 保留。当前基线27段、容量候选24段、短段组合候选25段；段数减少不是身份精度证据。组合候选出现两个句内多标签段落，需要逐段核对，不能仅按四个锚点放行。该证据也不等于手机 UI 截图验收。

Android 当前 Community 接口仍只传整窗向量，未传 Harmony 的独立 run 向量。共享 native 构建通过不能证明两端角色精度等价。这是既有平台能力差异，不是本次实验引入的回归；实施容量修复时必须分别绑定各自路径的证据。

下一步按独立提交处理容量与短段：先为容量溢出保留身份的行为补原失败红灯和相邻容量内不变量，再接入与当前 PCM 所有权一致的音量证据；短段查询保留为单独候选，解决新增归属错误后才考虑落地。禁止用增加 timeout、强制人数、抹去 UNKNOWN 或吞掉短换人让表格变绿。四锚点通过后才扩大实录和长时门禁。

本轮没有修改运行源码或重复构建。Qwen 尚未调用：未定位到用户所述凭据变量；没有尝试不相关密钥。现有 MOSS 继续仅作为辅助分桶，不是人工身份真值。
