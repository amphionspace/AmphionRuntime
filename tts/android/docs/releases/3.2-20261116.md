# Android TTS 3.2 交付记录

2026-11-16 行为修复版。产物 SHA-256、构建基线见 [JSON](3.2-20261116.json)。仅本地打包，未上传。

## 当前交付

相对客户在用的 3.1（2026-09-17）只修复缺陷 #94：句末标点紧贴下一句时（"ready?Yes"、"ready.Yes"、"Ready...Yes"）
`?`/`.`/`…` 被当成技术 token 读成 "question mark" / "dot"。模型（IMF 170000、24 kHz Vocos、173 token）、
推理参数、公共 API、资源内置与解包方式、授权公钥均与 3.1 相同；AAR 内 5 个 ONNX 与 3.1 记录逐一相同。

## 验证范围

- SDK 单测 157 项通过（含 #94 新增 5 项），4 项跳过；组包测试与仓库版本测试通过。
- 组包：`stageSdkDelivery` 以 IMF 导出目录为输入，`CHECKSUMS.txt` 8 项、ZIP CRC 通过。
- 真机（BRA-AL00 / Android 12，内部设备绑定授权，Release AAR 内置于 Demo）：`TtsLifecycleDeviceTest`（真实合成 + 停止/关闭/恢复 ×3）OK；
  `GluedPunctuationDeviceTest` 4/4 通过——"Are you ready?Yes, I am." / "Are you ready.Yes I am." / "Ready...Yes" / "你好吗?好的"
  与带空格写法合成出**逐字节相同**的 PCM（模型温度 0，前端 token 相同即输出相同），因此不另做人工试听。
- 构建输入说明：第一版 3.2 AAR 缺 `libonnxruntime.so` / `libonnxruntime4j_jni.so`（该分支从未跟踪这两个文件），真机
  `createEngine` 报 dlopen 失败；用清单校验过的 bundle `tts-onnxruntime-android-v1` 重编后 AAR 含三个 .so，上述真机结果均来自重编后的 AAR。
- 未重跑：完整 API 矩阵、1000 条长稳、完整发音语料、页面重建与双布局（本版未改相关代码）。
