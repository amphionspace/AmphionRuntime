# Dingqiao v3 Android 1000 条稳定性测试报告

测试时间：2026-07-13

## 结论

本次 Dingqiao v3 Android AAR 稳定性测试结论为：全部 success。



## 测试覆盖了哪些 case

本次测试集共 1000 条，目标是覆盖 SDK 日常集成、边界输入、稳定性和资源表现。样例类型如下：

| Case 类型 | 数量 | 主要验证内容 | 例子 |
|---|---:|---|---|
| 基础接口 smoke | 25 | 创建引擎、默认参数、基础合成链路是否可用。 | 冷启动后创建引擎并合成一句短文本；热启动后再次合成并查询 voice 列表。 |
| 引擎创建与查询 | 75 | 多次创建引擎、查询 voice、延迟加载等基础能力。 | 连续创建第二、第三个引擎；创建后查询 voice，再销毁引擎。 |
| WorkPath 与资源加载 | 75 | workPath 设置、资源解压、重复加载与释放。 | 设置新的 workPath 后加载模型资源；多次执行资源加载、合成、释放流程。 |
| 生命周期状态机 | 85 | start、stop、shutdown、重复调用等状态切换是否稳定。 | listener 设置前后调用 speak；空闲状态调用 stop；shutdown 后再次触发边界调用。 |
| 回调契约 | 55 | start、data、complete、error 回调顺序和数量是否符合预期。 | 合成中替换 listener；先置空 listener 再 speak；校验 start/data/complete 只出现合理次数。 |
| 请求队列与调度 | 80 | PREEMPT、队列切换、连续请求调度。 | 连续发起 PREEMPT 请求观察前一个请求被抢占；QUEUE 请求按顺序完成；PREEMPT 和 QUEUE 混合提交。 |
| 流式配置与缓冲 | 80 | chunk size、首包、缓冲容量等流式输出配置。 | 使用 chunkSize 16/32/64/100 的流式合成；调整 pcmQueueCapacity 后检查首包和回调。 |
| 播放通道与音频路由 | 45 | 播放模式、soundChannel、音频路由边界。 | 使用 SYNTHESIZE_AND_PLAY 直接播放；传入不支持的 soundChannel 并确认返回预期错误。 |
| 参数边界 | 65 | speed、pitch、volume、language、voiceId 等参数边界。 | 测试不同语速、音调、音量组合；使用 zh-en、zh-CN 语境和不同 chunk 配置。 |
| 错误校验与恢复 | 75 | 非法输入是否返回预期错误，并且后续请求能恢复。 | 空文本、超长文本、非法 language、非法 voiceId；重复 requestId 后再发正常请求。 |
| 长文本 TN 稳定性 | 80 | 600 到 3600 字长文本、中文 TN、重复文本合成。 | 合成包含日期、金额、电话号码、百分比的长中文文本；重复长文本合成观察 TN 和首包。 |
| 内存 soak | 110 | 多轮合成后的 Java/native heap、PSS、RSS 变化。 | 创建、合成、销毁循环；同一引擎重复 speak；长文本循环合成后检查内存。 |
| FD / 线程 / 进程资源 | 90 | 文件句柄、线程数、进程资源是否异常增长。 | TN 子进程循环启动；创建销毁循环后检查 FD；流式管线循环后检查线程数。 |
| 压力恢复回归 | 60 | 连续压力后 SDK 是否仍能恢复并继续合成。 | 非法输入后继续正常合成；TN broken pipe 后恢复；后台冻结风险场景后再次合成。 |

测试集中包含 897 条预期 PASS 样例和 103 条预期错误样例。预期错误样例用于验证 SDK 对非法参数或不支持能力能给出正确错误，不属于失败。

## 关键指标

以下指标基于本次 1000 条样例测试结果统计。

| RTF | 1000 | 0.23 | 0.21 | 0.25 | 0.93 |
| 合成耗时 synthesisMs | 1000 | 16.8 s | 4.3 s | 83.8 s | 399.2 s |
| 音频时长 audioDurationMs | 1000 | 77.5 s | 20.8 s | 349.0 s | 2139.2 s |

- 首包整体稳定，P95 为 247 ms，最大值 288 ms。
- RTF 平均 0.23，P95 为 0.25，整体低于实时播放要求。
- 最大合成耗时和最大音频时长来自长文本或长轮次样例，属于预期内的重负载样例。

## 结果口径

本报告按以下规则给出最终结论：

- PASS：正常成功。
- EXPECTED_ERROR：预期错误返回正确，计为成功覆盖。
- FAIL 但属于测试方法误报：不计入 SDK 失败。
- 长文本 timeout 且原因是测试超时设置不合理：不计入 SDK 失败。
- SKIPPED：不纳入结论。

按上述口径，本次 1000 条样例测试结论为全部 success。
