# TN 失败归因清单

测试集:`pronunciation-golden-round3-results-with-pinyin-fixed-round15.jsonl`(675 条)

## 0. 先纠两个"指标坑"

- **`phoneme_match` = 100% False**(675/675)。这个指标本身是坏的(golden 与 actual 只差边界 `_` 分隔符的表示)。**忽略它。**
- **真正信号是 `pinyin_match`**:**128 过 / 547 挂**。

## 1. 547 条 pinyin 失败的归因

| 类型 | 数量 | 判定依据 |
|---|---|---|
| **TN 域(TN 能修)** | **~408** | |
| ├ 数字未读成词(digit-by-digit) | 197 | golden 比 actual 长(展开了),tnText 还留着数字 |
| ├ 其它数字相关 | 77 | |
| ├ 时间/负号(3:05、-24.5) | 66 | `:`读成"冒号"、`-`读成"杠" |
| ├ 技术 ASCII(URL/邮箱/路径) | 61 | Kotlin 前端 `protect*` 处理 |
| └ 货币符号(¥/€) | 7 | ¥/€ 被错读成 "," |
| **G2P/下游(不是 TN)** | **~139** | |
| ├ 多音字/姓氏/专名 | 105 | **tnText 干净**,只是把 区/曾/解 读错音 |
| └ 单音节替换(多音字/声调) | 34 | 等长单点替换 |

**验证(硬证据)**:
- tn-numeric 失败 **147/147 (100%)** 的 `tnText` 仍保留原始数字 → TN 当时没读数字。
- polyphone 失败 **105/105 (100%)** 的 `tnText` 干净(仅标点归一) → TN 没问题,是 G2P 选错音。

## 2. ⚠️ 最关键发现:**这个测试集是"过期"的**

我用**当前源码**(submodule `9cf6411`,也就是交付要编的那份)编了 host `zh_tts`,把失败用例喂进去 —— **当前 TN 其实已经把测试集里"挂掉"的东西修好了**:

| 输入 | 测试集 tnText(挂) | 当前源码 TN 输出(对) |
|---|---|---|
| `3234.56 元` | `3234.56 元` | 三千二百三十四点五六 元 ✓ |
| `-24.5 度` | `-24.5 度`(读"杠二四") | 负二十四点五 度 ✓ |
| `4%` | `4百分号` | 百分之四 ✓ |
| `¥6.00、$6.99、€6` | `,6.00,美元6.99,,6` | 六元、六点九九美元、六欧元 ✓ |
| `3:05` | `3:05`(读"三冒号") | 三点五分(接近,见下) |

**147/147 数字失败用例,当前源码全部正确读出。** 说明这份测试集是在一个**没启用原生归一化**的构建上跑的(旧的/回退到过期 tn-bin 的那条路)。

→ **推论:那 ~408 条"TN 失败"里的大头(~340 数字/货币/百分号/负号)在当前源码里已经修好,只差"重新编译 + 重新基线",不需要新写规则。**

## 3. 当前源码里**真正还存在**的 TN 缺口(已抽验)

| 缺口 | 现状 | 应为 |
|---|---|---|
| **年份读法** | `2026 年` → 二千**零二十六**年(基数) | 二零二六 年(逐位) |
| **时间前导零** | `5 点 05 分` → 五点**五**分 | 五点零五分(需确认 Kotlin 前端 `hanziClockMinuteLeadingZeroRegex` 是否在整链里补零) |
| **货币小数尾零** | `¥6.00` → 六元 | 六点零零元(golden 要读出) |
| **技术 ASCII(URL/邮箱/路径)** | 逐字母 + 斜杠,和 golden 的英文字母音(EY1 CH T…)对不齐 | 复杂,部分 TN 部分 G2P |

这些才是**真正要动 rules_v2 / Kotlin 前端**的地方,数量比 408 小得多。

## 4. G2P/多音字(139 条)——**不在核心 TN 范围**

区(ōu/qū)、曾(zēng/céng)、解(xiè/jiě)这类姓氏/专名多音字,tnText 完全正确,是 G2P 选音错。**只能**通过 TN 的 `zh_pinyin.json`(发音映射)或加上下文规则去纠 —— 属于灰色地带、且需要上下文判断,建议和纯 TN 修复分开对待。

## 5. 建议的推进顺序

1. **先重新基线(最重要)**:用当前构建(AAR 已能编,含现编的 `liblits_tn.so`)把 675 条重新跑一遍,拿到**真实的当前通过率**。预计大幅跳升(数字类基本全过)。
   - ⚠️ 缺口:重跑到 `actual_pinyin/phoneme` 需要**生成这份测试集的那套 G2P/拼音抽取工装**(在设备上跑整条前端)。TN 这一层我能自测(比 tnText),但最终 pinyin 需要那套工装。**这个得找同事要,或确认怎么在设备上跑。**
2. 对**重新基线后仍失败**的用例再归因。
3. 修 §3 的真缺口(年份逐位、时间补零、货币尾零、技术 ASCII)。
4. 单独评估 §4 多音字(走 pinyin 映射 / 上下文规则)。

**一句话**:别对着这份过期测试集的 408 条硬修 —— 大头已经在当前源码里修好了。先重新基线,把真实剩余问题择出来,再动手。
